# awl docs — Platform: persistence, daemon, menu, session, updates, GPU, live feedback

> Read before touching `app/` lifecycle hooks, autosave/history, `daemon.rs`, `menu.rs`, `session.rs`, `updates.rs`, GPU fault/recovery paths, `--soak-gpu`, or the debug panel/HUD.

## Debug panel / HUD / copy pulse (determinism-safe live-only feedback)

- **Debug panel (`debug.rs`):** opt-in, dim top-right (the persistent margin outline owns the top-left), debug-only (diagnostic infra for the agent — the user screenshots, the agent triages). Value-only, no amber. Three perf lines (`frame ms`, `key→px ms`, `redraws`) + deterministic diagnostics. **Schedules zero frames** — rides frames the editor drew anyway, then draws one `still ·` stamp and goes fully quiet (0% CPU, frozen `redraws` — a climb without input is a hot-loop bug made visible). Toggle: palette "Toggle debug" / `Action::ToggleDebug` / `--debug` — **no default chord in either convention** (the emacs `C-x r` binding was retired when the native-first identity round dropped the emacs `C-x` defaults; rebindable via config `[keys] toggle_debug`). **Determinism:** perf lines are a live clock the capture lacks → a default `--screenshot` is byte-identical (panel absent); enabled-in-capture draws fixed numberless placeholders. Sidecar `debug` block.
- **Held stats HUD (`hud.rs`):** summon-while-held (Option-Cmd-I, a single chord; not a palette command — a discrete selection has no key-release). Centered card, stacked stats (file created, session time, word count, % through doc), ink×size, never amber. **Determinism:** session-time + file-created fold to `"—"` placeholders in capture (clock/fs the harness lacks); word-count + %-through are pure and shown. Both are over the USER'S DOCUMENT, not the shaped page: a collapsed fold and a History preview each substitute something else for what the renderer shapes, through `ViewState::substitute_text`, which keeps the document behind them — so folding a section does not change the word count, and a preview counts the manuscript rather than the diff transcript. `--hud` drives it. Sidecar `hud` block.
- **Copy pulse (arm decision in `actions/flinch.rs`, animation state in `caret/juice.rs`):** Cmd-C on a non-empty selection plays one gentle squash-pop + a selection-tint brighten, decaying back. It is a direct acknowledgement of the action under `DESIGN.md` §4's response law, not ambient motion. Arms via `copy_pulse_for` (`actions/flinch.rs`) at the apply seam (snapshots `had_selection_before` — `copy_region` clears the mark); the resulting `Effect::CopyPulse` plays through `CaretAnim::copy_pulse` (`caret/juice.rs`). Headless: no-op arm, settled state byte-identical, no sidecar field. **Live-only:** whether ~180–220ms reads as "obvious and understated".
- **Theme-switch settle readout (`themeswitch.rs`, debug-panel-only):** `theme latest` / `theme worst` / the phase breakdown ends at the new themed frame's **first successful present**. It measures reshape/atlas/present work, not the selection band's decorative tail; the flight recorder separately reports each prepared band phase and `theme-band input-to-settled`. The readout is retained in a trailing `SWITCH_WINDOW` wall-clock window (not a frame count, so cheap caret frames can't age it out). **`SWITCH_WINDOW` is 30s, raised from an original 5s (item 291):** the readout line carries no age indicator, and its own reader is "the user screenshots, the agent triages" — a human glance-over or an agent's read-then-capture round trip routinely exceeds five seconds, so the old window was an instrument that erased itself before it could be read. A pure dismiss-on-input design (never decay, only replaced by the next switch) was considered and rejected: with no per-line timestamp, an arbitrarily old switch's numbers could sit on screen looking current indefinitely, which is worse than disappearing.
- **Movement-latency probe (`probe.rs`, native live-only, item 85):** `mark_movement_input`/`note_presented_frame` pair every theme-picker movement step's input against its own first presented frame, through a FIFO queue (push on mark, pop-oldest on present) rather than a single overwritten slot — a single-slot version once collapsed an N-step burst to one sample and put a wrong number, off by roughly two orders of magnitude, on the project board (item 291). `probe::tests::movement_latency_burst_of_n_reports_n_not_one` sweeps burst length under the zero-gap arrival order (every mark before any present, the exact shape a fast arrow-key burst produces when input outruns the frame loop) and is mutation-proven: reinstating the overwrite fails it at `n=2`, the smallest burst where it can fail.
- **Conditional frame diagnostics:** every presented flight line reports the
  real interval since the prior successful present and the complete set of
  active animation reasons. An input that actually arms bounded motion also
  reports `input-to-animation-settled` when the last bounded activity retires;
  the travelling ground is ambient and does not hold an editing gesture open.
  This endpoint complements rather than replaces input-to-first-pixel and the
  theme work-phase measurements. The debug panel's final `still` stamp is one
  draw-once demand through the same reducer, then the window is fully idle.

## Autosave + local history (`app/files/autosave.rs` + `history/`)

- **Autosave (config `autosave`, default on):** quiet atomic writes (`fs::write_atomic`, temp+rename) on idle (~1s, single-`WaitUntil` debounce), blur, file switch, quit — one door, `App::autosave_flush`. **External-change guard (`crate::external` + `app/files/external.rs`):** the per-buffer baseline is a stat AND an FNV-1a digest of the exact bytes awl last saw, because mtime plus length cannot see a same-tick, same-length rewrite — **content decides**, so an identical rewrite is not a conflict and a same-size one is. `App::settle_external_change` is the one guard, asked at focus return, buffer activation, idle/blur/quit autosave, manual Save, Finish file, rename and move. Three outcomes: write; reload a CLEAN buffer keeping cursor + scroll; or latch a conflict — the buffer stays the sole editable document, writes to the path stop, and the unsaved text goes to the ONE recovery record (`crate::recovery`, `data_root()/unresolved-change.md`, the scratch-stash pattern) so a kill cannot take it. Resolved only by **Save your version** (rechecks disk first) or **Use disk version** (one undoable `set_text`); both palette rows are hidden unless a conflict is open (`commands::RowGates`). Quit is deferred once, then proceeds — the record makes it lossless. **A manual Cmd-S no longer force-writes.** Scratch buffer stashes to `fs::scratch_stash_path()` on the same triggers and restores on a no-arg launch (`App::new` only). **Seeing both versions (item 204 slice 2):** the guard's own line is a NOTICE — one slot, cleared by any toast expiring — so the durable signal is chrome instead: a persistent `changed elsewhere` line above the filename in the page-mode gutter (`render/chrome/gutter.rs`, sidecar `gutter.changed`; page-mode only and hidden under overlays, like the rest of that block). The palette's gated **Review the change** row opens `OverlayKind::Conflict`, a `TimelineOverComparison` workspace whose three rows are the read-only views **Differences / Your version / Version on disk**, resolved through the ONE dispatch `crate::comparison::prose_for` (History's producer and the conflict's, one resolver, no second renderer). Previews never touch the buffer — not even its version — and `Esc` returns to editing UNRESOLVED; both resolutions stay their own named palette rows. **Tripwire: a conflict is reachable headlessly only through `--screenshot-app --seed-data DIR`** (docs/harness-reach.md #3): nothing can raise one mid-run, because the change must come from outside awl.
- **History:** every save records a snapshot (`history::record`, deduped). **Tripwire: git-managed files record no snapshot, ever** (their timeline is `git log` alone). Loose files snapshot on every save. **Pruning = the aged retention ladder** (`prune_ladder`, pure fn of `(store, now_ms)`, injected clock): keep everything ≤15min, one/session to 24h, one/day to 30d, one/week older, cap ~150 by climbing harder — never FIFO; the oldest snapshot always survives. Prune resolution, not memory.
- **Tripwire: determinism:** the whole engine lives only on the live App (armed in `sync_view` behind the gpu-present gate, flushed by App-only hooks). The headless capture is structurally autosave-free. AUTOSAVE is live-only; **the NOTICE is not.** The notice channel has ~ten production callers and several — a refused Export, a failed rename, the line-endings flip — are reachable headlessly, so `CaptureOpts::notice` carries it and the sidecar reports it as `notice: { text, kind }`. It photographs on both the ordinary `--keys` door (the replay latches `Effect::Notice` instead of discarding it) and `--screenshot-app`. Only the notices an autosave raises are live-only.

## Document export destination (`app/files/export.rs`)

- **One owner for "where does it land".** `export_target(doc_path, root, stem, format, dest_dir)` is pure — no `App`, no filesystem — and is the only answer to the question. `dest_dir` is the root-relative folder the writer chose; with `None` the two defaults stand. A document WITH a path exports as its own sibling (`doc.md` → `doc.pdf`), so a repeat export overwrites its previous snapshot instead of accumulating copies. A buffer with NO path exports into the **active folder** (`project_location.root`) under the name the buffer already calls itself (`web_export::export_stem`, i.e. `display_name()` minus the markdown extension — never a second naming rule). On a first-run bare launch the active folder is `fs::data_root()`, which is why that case is the one a writer cannot predict.
- **The notice's rule is a RELATION, not a flag per arm.** `ExportTarget::at` speaks the whole path unless the file landed in the folder the document itself lives in — the one folder already on screen. Stated that way, every route to a destination (sibling default, active-folder fallback, a folder chosen in the navigator, a folder chosen in a save panel) reads one rule; a flag per arm had reached two arms and each new door would have set it by guess. That line is the anti-surprise mechanism, so it is law-tested on both sides of the path axis AND on the case a per-arm flag got wrong — choosing the document's own folder, which must read exactly like the sibling default. `app::files::export::tests` also holds a differential oracle pinning the destination arithmetic against the spelling it replaced, and tier-2 laws driving a real headless `App` over `InMemoryFs` to assert the file appears at both the default and the chosen destination carrying exactly the bytes `export::to_bytes` emitted.
- **An export asks WHERE before it writes, on every platform that has a folder to offer.** `actions::export_picks_destination(platform)` is the one predicate: on native the shared core summons `OverlayKind::ExportDest` — a folders-only walk of the active root, title "export to", the same navigation grammar as `MoveDest` through the shared `OverlayKind::is_folder_destination` — and nothing is written until its accept emits `Effect::Export(format, Some(dir))`. The FORMAT rides the card (`OverlayState::export_format`) because the action chooses it and the accept reads it, with any number of level rebuilds in between; `Journey::relevel` carries it forward through `OverlayState::carry_level_payload_from`, the same mechanism `Bind::Path` uses for a Settings folder key, and the law that pins it descends and ascends before accepting. On the WEB build the bytes go to the browser's own download, which owns where they land, so nothing is chosen and no surface opens.
- **Reveal after writing is macOS-only and LIVE-only.** A successful write asks the Finder to select the file (`mac_chrome::reveal_in_file_viewer` → `NSWorkspace activateFileViewerSelectingURLs:`). Gated on a real SURFACE, not on `cfg`: `App::reveal_path` (generalized beyond export to also serve the "Reveal in File Manager" command) returns early when `frame.gpu().is_none()`, so `--screenshot-app` and every test take the identical write path and reveal nothing. Without that gate, running the suite on macOS opens a Finder window per export test — the law that pins it reads the returned "did it fire" boolean, since the AppKit call itself is not observable from a test process. **Flagged for human confirmation:** whether the Finder coming forward is wanted (it takes focus from the editor) is a live taste call no capture can make.
- **A capture never performs an export.** `Effect::Export` classifies **Intercepted** at tier 1 (`docs/harness-reach.md`) — recorded with its extension, not written — so the destination and the reveal are asserted at the unit and tier-2 seams, never from a `--keys` sidecar.
- **macOS answers the three File-menu Export rows with a real `NSSavePanel`**, opened at the folder and under the name the destination owner would have chosen on its own — so the platform's own "where does this go" wins over the in-app card on the MENU door only; the chord and the Cmd-P palette row keep the `ExportDest` navigator on every platform. ⚠️ `runModal` blocks the process MAIN THREAD until a human closes it, so `export_via_platform_panel` returns early when `frame.gpu().is_none()` — deliberately the SAME surface gate the reveal uses, not a second one. Without it a surfaceless `App` would hang `cargo test` and `--screenshot-app` forever, with no output and no timeout; the law reads the returned "did the door open" boolean, exactly as the reveal's does. Linux has no save panel: the in-app navigator is the whole answer there, on every door including the drawn menu bar's — **an arm no macOS host can run.**
- **The three Export labels carry the ellipsis again, and it is FALSE on exactly one platform.** A native panel is a second door onto the ellipsis promise that `apply_transition` cannot see, so `menu::NATIVE_PANEL_IDS` declares that door as data and `menu::ellipsis_law` holds all three: the label agrees with the shared core on every platform, a platform panel only ever lands on a row that already promised a surface, and the set of platforms the one static label over-promises to is exactly `{Web}` — where the browser opens the surface, not awl. Dropping the ellipsis instead would make it false on macOS AND Linux, where a surface genuinely opens; a cosmetic over-promise on one build is the cheaper lie, and it is pinned in both directions rather than left as a comment.

## Line endings (`buffer.rs`) — the VS Code model

- **Invariant:** the rope is always pure `\n`, so buffer and the `\n`-only renderer agree by construction (the old CRLF/lone-CR divergence is gone). ropey built with `unicode_lines`/`cr_lines` off — breaks at `\n` and nowhere else (never CR/CRLF/NEL/LS/PS).
- `Buffer::eol {Lf, Crlf}` remembers the file's ending (`Eol::detect` = dominant). Load normalizes `\r\n`→`\n` before the rope; save restores via the one encoder `Buffer::disk_bytes` (every write site routes through it), so a CRLF file round-trips byte-for-byte and an LF file is byte-identical. `text()` is the internal pure-`\n` view (unchanged). A lone `\r`/NEL/LS/PS is content, not a break.
- **Design choice:** EOL is document metadata, not on the undo timeline (Cmd-Z doesn't restore it — mirrors VS Code). `set_eol` bumps version + marks dirty.
- **The flip announces itself.** `Action::ConvertLineEndings` (palette-only, unbound) changes nothing on screen and nothing on the undo timeline, so with no notice a double invocation was indistinguishable from none and a single one from nothing happening. It raises a toast naming the convention now IN EFFECT (`line endings: LF` / `line endings: CRLF`) — the resulting state, never the event, because "which one am I on" is the question.

## Daemon (`daemon.rs` + `app/daemon.rs`) — single instance + CLI handoff (native only)

- One `awl` per machine. Startup binds a Unix socket at `fs::data_root()/awl.sock`. Bind success = this is the instance. Bind fail + connect succeeds = hand the launch `file` off and return in ms (no window). Bind fail + connect refused = stale socket, unlink + reclaim. Unlinked on clean quit.
- Dumb newline protocol (`open <abs-canonical-path>[ wait]\n`). The client canonicalizes the path itself (`normalize_path` — the server can't recover the client's cwd). `spawn_accept_thread` blocks on `accept()` (0% CPU idle) and posts `DaemonEvent::OpenPath` into the winit loop via `EventLoopProxy` (never cross-thread `App` access).
- **`--wait` (EDITOR=awl for git):** server replies `ok`, then `done` once the buffer finishes via the **"Finish file"** palette command (`Action::FinishBuffer`, default `Cmd-W`; the emacs `C-x #` default is retired) — saves + notifies waiters + switches away. A Waiter's socket closing without `done` is an equally valid done (never hang).
- **Palette gating (2026-07-22, user-decided):** the "Finish file" palette row is hidden unless a `--wait` client is actively parked on the CURRENT buffer (`App::wait_conns`) — with nothing waiting there is nothing to finish. `commands::visible_hidden_mask(RowGates)` is the pure predicate (unit-tested) — `RowGates` now carries three live facts (`has_waiter`, `change_unresolved` for the conflict-resolution rows, `named_file` for Reveal/Copy-path), not `has_waiter` alone. `OverlayState`'s new `hidden` mask (parallel to `corpus`, consumed by `refilter`, mirroring the dotfile display filter) drops the row from what's rankable/selectable WITHOUT shrinking `corpus` itself, so the row-index math `commands::visible_action_of` relies on for every other row never shifts. `BuildCtx::has_waiter` carries the one live fact in; it's `false` everywhere but the live App (structurally, on the headless capture/replay path, and on wasm/`mas` where the daemon doesn't exist), so a default palette hides the row deterministically. **Dispatch is unchanged** — the chord bound to it / a shown row still runs the same `Action::FinishBuffer`. The rebind menu (Keybindings…) is NOT gated (you can still bind a chord to it ahead of ever using it).
- **Tripwire: capture gate:** every daemon door lives only on the live App's startup (`crate::app::run`); `--screenshot`/`--keys` never import `crate::daemon`. `FinishBuffer` emits the ordered typed requests save → notify → previous buffer. Ordinary replay owns no filesystem capability, intercepts the notification, and records the unsupported save/switch without performing them. A strict scenario may save only through its explicitly granted isolated sandbox. No daemon sidecar.

## GPU failure paths + --soak-gpu (app/gpu.rs + soak_gpu/)

- `GpuFaultKind {OutOfMemory, Validation, Internal, DeviceLost, SurfaceRecoveryFailed}` → a `FaultSlots` inbox drained per-frame; recovery is App-owned and bounded. Editor buffers live on App, not on Gpu — state survives a full GPU rebuild.
- Hidden flags `--soak-gpu` / `--soak-gpu-seconds` (default 15min): a deterministic `Stimulus` schedule (Resize/ThemeNext/Overlay/SetLavaTheme/Inject(FaultKind)) with per-kind SkipKind counters. `--soak-gpu` is isolated (rejects file/capture/input/config args) and structurally live-only (capture-gated).
- **Tripwire: the wgpu macOS occlusion gate:** wgpu-hal 29.0.3 (metal/surface.rs, the wgpu#8309 workaround) returns `SurfaceError::Occluded` before `nextDrawable()` whenever the NSWindow lacks `NSWindowOcclusionStateVisible` — hidden window, `.with_visible(false)`, display asleep/locked, occluded-behind-other-windows, non-interactive launch. Symptom: `acquires=0 presents=0` all-skipped (or a stalled surface-lost recovery — a background 2026-07-17 soak measured surface_lost recovery at 94.5s purely because the window sat occluded; memory was flat, RSS slope negative, Metal peak 43MB). It looks like a zero-drawable GPU bug but is the OS occlusion state — check window visibility before touching the GPU path. A soak run must keep its window foregrounded to meet the contract.

## Native macOS menu bar (`menu.rs` + `app/menu.rs`)

- The real AppKit/muda bar this section covers is macOS only (`cfg(target_os = "macos")`). **The law:** every item fires an existing `Action` via `App::apply` — never a menu-only path. `menu::roster` + `menu::resolve` share one id→command table (`menu::SECTIONS`), law-tested against the catalog (a typo'd name fails a test).
- **Tripwire: Quit + Edit items are routed, not muda predefined.** Predefined Quit sends `terminate:` (bypasses `App::exiting` → skips autosave/session/daemon teardown); predefined Cut/Copy/Undo send responder-chain selectors a raw wgpu `NSView` doesn't implement (silent no-op). Don't "simplify" them back to predefined.
- **Tripwire: `install()` must keep the returned `muda::Menu` alive** (`App._menu_bar`) for the app's lifetime: native `NSMenuItem`s hold non-retaining pointers back into the Rust `Menu`; dropping it = use-after-free on the next click (the menu-click crash). Menu labels stylize "Awl"; the App-menu title is forced to the process name by AppKit (needs a real `.app` bundle — banked).
- **Icons (`menu_icons.rs`):** `safe_icon` validates dims + buffer length before `muda::Icon::from_rgba`, never `.unwrap()`s (the literal guard against the crash class). Small procedural set (New document, Save, Switch theme).
- **The platform-panel rows are declared data, not a literal in the handler.** `menu::NATIVE_PANEL_IDS` names every id the macOS menu answers with a real AppKit panel instead of dispatching its routed action — `awl.open` (`NSOpenPanel`) and the three `awl.export_*` rows (`NSSavePanel`) — and `menu::opens_native_panel` is the one predicate `App::handle_menu_event` asks, with `App::run_native_panel` routing each claimed id to its panel through the roster's OWN `resolve` table rather than a second id list. Only the MENU is redirected: the keyboard chord and the Cmd-P palette row keep the in-app overlay on every platform. Held as data because a panel is a surface a label's ellipsis promises, and `ellipsis_law` can only sweep both doors if both are readable from any host (no `cfg!` in the law).
- `build_menu()` + icons are live-only (main-thread muda panics off-thread); `roster()` data is unit-tested; menu install is on `resumed()` only (capture-gated). **Live-smoke:** `scripts/smoke-menus.sh` (`--print-menu-roster`; never runs the test instance under the name `awl` — two same-named procs resolve unreliably through the Accessibility API and could drive your real instance).

## Awl-drawn web/Linux menu bar (`menubar.rs` + `render/chrome/menubar/`)

- Off-macOS platforms are NOT bare of a menu bar: `menu_bar_on()` defaults ON everywhere but macOS (`menubar::MENU_BAR_DEFAULT_OTHER`, off on macOS since a real system bar already exists there) and draws the same shared `menu::roster()` as its own strip + anchored dropdown, reading it through `crate::menu`/`render::chrome::menubar` rather than muda/AppKit. Its chord column is CONFIG-AWARE: `[keys]` overrides and `Config::effective_linux_keep()` (the `keymap` flavor preset + `linux_keep_emacs`) suppress a chord to an empty cell rather than showing one the resolver would not actually dispatch, through the same owner (`commands::menu_native_label`) the command palette's chord labels use.
- `AWL_MENU_BAR_FORCE=on|off` is the dev-only knob for driving the OTHER platform's default from any host (docs/config.md); `scripts/native-gate.sh` sweeps both branches on every gate.

## App icons (`app_icon/` + `assets/macos/`) — macOS only

- **The set.** One pre-rendered icon per world. The lockup is `aw` plus an ordinary lowercase `l` in the world's display face — one inline run of text, so same size and same baseline are structural — with a deliberately FAKE logo-cursor behind the `l`: **never** awl's live Block/Morph/I-beam caret renderer, and it never moves. Exactly three shapes (`IconCursor::{Block,Pill,Narrow}`), declared on the `Theme` itself, so a new world cannot compile without choosing one. Colours are the world's own `base_100` / `base_content` / `primary` / `primary_content`; ambient grounds (lava, the warped grid's travel, an `AmbientStyle` layer) flatten to `base_100` — an icon is one still frame.
- **Rendered ahead of time, never at runtime.** `scripts/export-icons.sh` drives a pinned, offline Chromium (zero network, fonts inlined from `assets/fonts` as data: URLs) and then `awl --pack-icns` cuts each world's tiles into a real `.icns`. `cargo build`, `cargo test` and the shipping app invoke **no browser and no wgpu renderer** — they only read committed bytes. The pack step is pure Rust (no `iconutil`), which is what lets a unit test re-pack a committed asset and demand identical bytes.
- **Two consumers, deliberately different.** `Contents/Resources/Awl.icns` (`CFBundleIconFile`, wired by `scripts/package-macos.sh`) is the DEFAULT world's icon and never changes at runtime — a bundle icon belongs to the bundle, so Finder is stable. The RUNNING app's Dock / ⌘-Tab tile follows the active world via `app_icon::adopt` → `mac_chrome::set_dock_icon` → `NSApplication.setApplicationIconImage:`.
- **Tripwire: the Dock must not churn on a hover.** `adopt` is reachable from exactly TWO places, both settled: `resumed()` at startup (after `Config::apply_sticky_globals` has restored the sticky theme) and `App::post_transition_effects`'s `theme_committed` arm — the same guard that decides whether the sticky preference is written. The picker's live PREVIEW (`retint_theme_preview`) has no route to `app_icon` at all, so arrowing or sweeping through twenty worlds moves the Dock zero times structurally, not by politeness. `app/tests/dock_icon.rs` counts adoptions across a full preview sweep.
- **Capture gate:** the AppKit call is live-only (a headless or off-main-thread process has no Dock tile) — but `adopt` records the adoption either way, which is what makes the no-churn law observable without a Dock.
- Laws live in `app_icon/tests.rs`: the world↔asset bijection, the pinned preset roster, container validity (full rep roster at the declared sizes, parsed by our own strict reader AND decoded by AppKit), byte-deterministic re-packing, and pixel arithmetic for the four theme tokens, the `l`'s stem + shared baseline, safe-area clearance measured against the squircle, and pairwise distinction at app-switcher size. The web favicon is the paired one-glyph composition from the same exporter.
- **The Linux launcher icon (item 227) is CUT from this same pipeline, not a second render.** `--export-linux-icon` (`src/main/args.rs`, `app_icon::icns::linux_icon_png`) parses the committed canonical `assets/macos/Awl.icns` with the same `icns::unpack` the macOS law tests use as their oracle and pulls out its 256px chunk — the DEFAULT world's own artwork, byte-for-byte, never re-rendered. `scripts/package-appimage.sh` is the one caller; see RELEASING.md's AppImage section.

## About window (`mac_about/`) — macOS only

- **What it is.** awl's own `NSPanel`, replacing `orderFrontStandardAboutPanelWithOptions:` (the generic panel every app that ships it looks identical in). Composition: the shipped app icon at 128pt, `Awl`, one product line, the provenance block, `Frank Lu · GPL-3.0`, and Docs / GitHub buttons — separated by air alone, with **nothing drawn between them**. Titled + closable + `FullSizeContentView` with a transparent, title-less titlebar, so the card owns the whole surface and still reads as macOS. App menu ▸ "About Awl" and Cmd-P ▸ "About" both reach `Action::About`; the shared transition emits `SurfaceEffect::ShowAbout`, then the live interpreter shows the native panel on macOS or the in-app `about.rs` card elsewhere. Headless replay deterministically opens the in-app card.
- **Tripwire: who owns the window.** A main-thread-only `thread_local` holds the sole `Retained<AboutPanel>` for the process's lifetime. `releasedWhenClosed` is YES by default for a programmatically created `NSWindow`, so without `setReleasedWhenClosed(false)` the close button frees the window out from under that `Retained` and the next About is a use-after-free — the dropped-`muda::Menu` hazard in a second costume. Both buttons target the panel itself: unretained by AppKit (no cycle), outlived by the panel (no dangle). Summoning twice raises the one window; `show_reusing` is the shape that guarantees it.
- **Facts are read, never invented.** Version = `CFBundleShortVersionString` when packaged, else `CARGO_PKG_VERSION`. Build = `CFBundleVersion`, shown only when it differs from the version. Commit = `AWL_GIT_COMMIT`, stamped by `build.rs` from `git rev-parse --short=12 HEAD`. **There is no placeholder anywhere:** an unknown fact loses its line and the window gets shorter (`layout` takes the line count), because "unknown" sitting in a facts block reads as a fact. `build.rs` emits no timestamp or hostname, so two builds of one tree stay identical.
- **Zero network holds.** The panel fetches nothing; Docs and GitHub hand a fixed compile-time URL to `NSWorkspace` only on a click, with the destination in each button's tooltip. Neither URL carries a query, fragment or version.
- **Two ink roles, and no third.** The whole typographic hierarchy is `Ink::Body` (the name, the product line, the credit, the button labels) and `Ink::Secondary` (version/build/commit, and only those). Only the name steps away from `BODY_FONT_SIZE`, and only in size and weight — never in ink. `ink_color` is the one resolver, matching with no wildcard arm, so a third colour cannot be spent without a new variant that the roster law refuses. Both roles are AppKit semantic colours, so light and dark are correct with no hardcoded palette.
- **Tripwire: the two-ink law is asserted over PIXELS, per element.** A source-side roster alone would say nothing about what AppKit drew, and could not see a rule, a box or a bezel. `mac_about/ink.rs` reads committed captures of the packaged app (`tests/fixtures/about/{light,dark}.png`, `CGWindowListCreateImage` at 2x) and asks each label's own frame what colour it drew in; `distinct_roles` collapses the answers and the law demands two, with the grey the quieter. A first attempt histogrammed the region instead and reported **seven** roles for this two-role window — every rung of the antialiasing ramp counted as an ink — so `element_ink` reads a percentile into the covered pixels, and the synthetic tests render ramps on purpose. `divider_rows` finds a rule by SHAPE (a thin, long, isolated horizontal band), so any way of drawing one trips it.
- **Fixture staleness, stated not glossed.** `fixture_geometry_still_matches_the_layout` pins each capture's pixel size to `layout::content_height`'s own arithmetic, so a geometry change fails until the capture is retaken. A pure colour change that leaves geometry alone is the one edit that coupling misses; the source-side roster catches that instead. Neither end is sufficient alone.
- **Not a theme surface.** The artwork is `icon_bytes()` — the canonical bundle icon — never `applicationIconImage`, which `app_icon::adopt` swaps per world.
- **Capture gate:** the AppKit half is live-only (a `--screenshot` run has no window server). What IS mechanically checked: every word (`facts.rs` — the placeholder sweep over the whole knowledge lattice, plus the tagline/credit/URL pins to README, NOTICE, Cargo.toml and `site/`), every frame (`layout.rs` — swept over 0..=4 provenance lines for zero extents, bounds, overlap, centring, traffic-light clearance), every ink and the absence of any divider (`ink.rs`, over real captures), single-window reuse, the Esc / Cmd-W contract, the icon's identity, and the routing sweep across the full command roster. **Whether the composition reads as authored is human-confirmed, never claimed by the harness.**

## Running awl on macOS in development (`scripts/dev-app.sh`) — macOS only

- **The supported dev launch is `scripts/dev-app.sh`, not `cargo run`.** It builds (`--release` by default — feel is judged there), assembles `target/dev-app/Awl.app` through `scripts/package-macos.sh` (the same canonical `Info.plist` writer and the same committed `assets/macos/Awl.icns` a release uses — there is no second source of product identity), registers it with LaunchServices, verifies the identity contract, and opens it. `--debug`, `--no-launch`, and `-- <args to awl>` are the knobs.
- **What a bare binary cannot do, measured 2026-07-29 (item 167).** macOS reads a live app's product identity out of its BUNDLE, not out of the process:

  | surface | bare `target/release/awl` | `scripts/dev-app.sh` bundle | source macOS reads |
  |---|---|---|---|
  | menu bar (app menu title) | `awl` | `Awl` | `CFBundleName`, falling back to the process name |
  | Stage Manager tile | **no icon at all** | the canonical Awl icon | the icon LaunchServices registered for the bundle |
  | ⌘-Tab name | `awl` | `Awl` | same as the menu bar |
  | ⌘-Tab / Dock icon | the active world | the active world | the running app's own `setApplicationIconImage` |

- **The limitation is real and is not worked around.** The menu-bar name and the Stage Manager icon **cannot** be fixed on a bare binary: neither consults anything the process can set at runtime, and the only lever left would be spoofing the process title — which lies about what is running. awl does not do that; it ships the bundle instead. A bare `cargo run` is still perfectly good for everything except those two surfaces, and it is not advertised as equivalent.
- **Tripwire: assembling the bundle is not enough for Stage Manager.** A locally built `.app` in a build directory is not somewhere LaunchServices has looked, and until `lsregister -f` runs, Stage Manager draws the **generic blueprint tile** — the exact defect item 167 was raised for, still present on a freshly assembled bundle. `dev-app.sh` registers it; a release never needs to, because dragging `Awl.app` out of the DMG into `/Applications` registers it. Dropping that call would silently regress the surface and nothing else in the repo would notice, which is why `macos_identity_law.rs` asserts it.
- **The two icon consumers stay split (unchanged).** Stage Manager and Finder read the BUNDLE icon, so they always show the canonical default-world artwork and never follow the session. The Dock and ⌘-Tab tiles follow the active world through `app_icon::adopt`, exactly as before — a theme *commit* adopts once, a preview sweep adopts zero times (`app/tests/dock_icon.rs`).
- **The identity contract has one owner:** `verify_bundle_identity` in `scripts/package-macos.sh`, called by the assembly path and by `scripts/package-macos.sh --verify <app>` (the native packaging gate). It asserts `CFBundleName`/`CFBundleDisplayName` = `Awl`, `CFBundleExecutable` = `awl` — the displayed name is capitalised, the typed command is not — plus `CFBundleIconFile` and that the bundled `Awl.icns` is byte-identical to the committed canonical one. `macos_identity_law.rs` guards the structure of all of it, since the surfaces themselves are live-only.

## Session restore (`session.rs` + `app/session.rs`) — native only

- A plain relaunch reopens the previous session: open files, the active one, each file's cursor/scroll (small ints, never a content snapshot — disk is the source of truth), and the window frame. Composes with the scratch stash (which still owns the no-path scratch buffer).
- Closing the last document persists `document_active = false` beside the remembered root. A bare relaunch restores that intentional absence and its folder; a missing or legacy session has no such marker and keeps the ordinary first-launch scratch.
- Storage: `fs::data_root()/session.toml` (hand-rolled TOML, beside the stash — deliberately not in `config.toml`, which is the user's file). Malformed/missing → empty session, never a crash. **Flush** on the same blur + quit triggers as autosave (not idle/switch — the file set changes rarely, and capturing the frame every resize-frame is wrong). **Restore** once from `App::new` after the stash restore: vanished files skipped, survivors parked into the registry, a bare launch adopts the remembered active, a file-arg launch keeps its file active with the session behind it.
- Window frame re-clamped in `resumed()` against connected screens (`clamp_frame_to_screens`, pure). Config `session_restore` (default on) vanishes both halves. **Tripwire: capture gate:** live-App-only; `replay_keys`/`load_buffer` build a bare `Buffer` and never touch the session file.
- **Item 76 — the one active-folder-context owner + the one launch-precedence law.** `SessionState.root` is written by `session_flush` in the SAME atomic write as `active`/`buffers`, so the folder and the restored document can never disagree (the old, separate `config.project_root` key — which could drift from the session's own `active` — is retired). `switch_project` also flushes EAGERLY (not only on blur/quit), so a crash right after a folder switch still resumes the new folder. The windowed launch door (`main/run/location.rs::resolve_launch_context`) is the ONE function every bare/explicit launch resolves through: (1) an explicit `--root`, or a file/dir argument (`awl .` included) — wins outright, unaffected by anything remembered; (2) a bare `awl` restores the remembered folder via `crate::session::remembered_root()`, gated on `session_restore_on()`; (3) nothing remembered (first run, or the kill-switch is off) opens the configured `default_folder` when the user has actually set one, else falls to `fs::data_root()` (`~/.local/share/awl` and platform equivalents) — `~/notes` in `docs/config.md`'s commented-out template is an illustrative value the user must opt into, not the shipped default — replacing the old cwd fallback. **Tripwire: capture is structurally free of this too** — every headless capture mode resolves its root through the separate, explicit-only `resolve_root` (never remembered, never `default_folder`; a bare `--screenshot` still falls to cwd), since a capture invocation is never a "terminal/desktop launch" in the product sense.
- **Retired (item 76):** the "Notes" two-desk flip (`Action::NotesFlip`, the `notes_return`/`notes_last_file` fields, `files::DeskReturn`) — there is now exactly one active folder, so there is nothing to flip between. `New document` (Cmd-N, renamed from "New note") creates a fresh, unnamed document IN the active folder rather than jumping to a separate notes home; its filename derives from the first line ONCE, on the first material save (`Buffer::save` clears the fresh-document marker in the same step) — a later edit to the first line never renames it again. Move (`C-x m`) target folder is the active root, same as Browse.

## Check for Updates (`updates.rs` + `site/check.*`) — the app stays network-free

The site compares against its own same-origin `version.json` (generated at deploy, never committed).
- The About card gains a quiet "checked … ago" line (`sync_update_checked`, mirrors `HudSaved`). Headless: field stays `None` → fixed `"checked —"` placeholder; `Effect::CheckForUpdates` is a headless no-op. A startup/ambient check was rejected (dilutes zero-network, is launch telemetry by another name).
