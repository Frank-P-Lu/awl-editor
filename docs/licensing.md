# awl docs — Licensing, credits & supply chain

> Read before touching licenses, bundled assets, dependencies, `cargo audit` findings, or release paperwork. Moved verbatim out of CLAUDE.md 2026-07-22 (queue item 17); earlier round history: `git log -p CLAUDE.md`.

## Licensing & credits

- awl's code is **GPL-3.0-only** (`Cargo.toml`, flippable to `-or-later` — sole copyright holder's call); `NOTICE` states copyright. Bundled-asset licenses live beside them (`assets/fonts/LICENSES.md` all-OFL; `assets/dict/LICENSES.md` records `en_GB` under LGPL-2.1 and the verified SCOWL permissive grant + Ispell BSD terms covering `en_US`/`en_AU`). **Never fabricate a license fact — flag what's unverifiable.**
- **The licence set travels with the binary, and packaging enforces it.** The fonts and dictionaries are `include_bytes!`d, so a downloaded awl *contains* OFL and LGPL-2.1 material — `assets/fonts/LICENSES.md` and `assets/dict/LICENSES.md` therefore ride every artifact alongside `LICENSE`, `NOTICE`, `CREDITS.md` and `THIRD-PARTY-LICENSES.md` (`scripts/package-linux.sh` → the tarball's root + `licenses/`, exiting non-zero on any missing file; `scripts/package-macos.sh` → `Contents/Resources/` + `Resources/licenses/`; `scripts/package-appimage.sh` (item 227) → the AppImage's `usr/share/doc/awl/` + `licenses/`, same non-zero-on-missing rule). Item 226 found the asset pair documented as shipping and copied by nothing. The tarball's `README.txt` (mirrored inside the AppImage) carries the GPLv3 §6(d) source offer; RELEASING.md §4 is the per-artifact table.
- `THIRD-PARTY-LICENSES.md` is generated (`cargo about generate about.hbs -o …`), never hand-edited; `about.toml` is its license-inventory owner. `deny.toml` independently blocks license drift across the full product graph using the resolved GPL-compatible license choices; it does not make claims about bundled assets. `CREDITS.md` (warm, PHILOSOPHY voice) is `include_str!`'d; Cmd-P → "Credits" opens it (`App::open_credits` refreshes a real on-disk copy first — a path-less buffer reads as scratch to autosave and would clobber the stash).

## Supply chain

- **Run `scripts/audit.sh` each merge-train day** (install exactly `cargo install cargo-deny --version 0.20.2 --locked`). It is the sole dependency-policy gate: RustSec advisories and yanks, licenses, duplicate crate versions, and registry/git sources. It checks the macOS, Linux, and wasm targets with all features, including the macOS `mas` flavor. Semver-compatible fix → `cargo update -p <crate>` (minimal, never major; `wgpu` stays exact-pinned) + the targeted test slice. No non-major path → record one narrow advisory ID, risk note, and removal condition in `deny.toml`; cargo-deny fails an ignore that no longer matches the graph.
- Standing accepted findings (no non-major path): RUSTSEC-2026-0194/0195 (`quick-xml` 0.39.4, gated behind a `winit 0.30` bump via `wayland-scanner`; parsed XML is the build-time Wayland protocol spec, not attacker input) and RUSTSEC-2026-0192 (`ttf-parser`, unmaintained, no patch short of a font-parser swap). Their exact rationales/removal conditions live only in `deny.toml`; re-check when an upstream `winit`/`cosmic-text` release picks up the fixes.
- **The AccessKit tree (item 207, 2026-08).** Native accessibility added 55 crates in one go — `accesskit`, `accesskit_winit`, and the per-platform `accesskit_macos`/`accesskit_unix`/`accesskit_windows`/`accesskit_ios` adapters over `accesskit_consumer`, plus the Linux AT-SPI stack they pull (`accesskit_atspi_common`, `atspi*`, `zbus*`, `zvariant*`) and its async runtime (`async-io`, `async-executor`, `blocking`, `futures-lite`, `event-listener`, …). Every one is permissive per its own published manifest: `MIT OR Apache-2.0` for the AccessKit crates and most of the tree, plain `MIT` for the zbus/zvariant/phf families, and `Apache-2.0` alone for `accesskit_winit` — Apache-2.0 is one-way compatible with GPL-3.0, which is the direction awl needs. Nothing new was added to `about.toml`'s `accepted` list or `deny.toml`'s `allow` list; the whole tree resolves inside what was already permitted. **Flagged as unverifiable from the artifact:** the AccessKit `.crate` archives ship no `LICENSE`/`COPYING` file at all, so the SPDX identifier comes from the published `Cargo.toml` alone and `cargo about` renders the canonical SPDX text rather than an upstream copy. Their repository states the same dual license; that statement was not independently re-verified here. The bump also forked four crate versions (`syn`, `toml_edit`, `toml_datetime`, `winnow`) — the AT-SPI macro stack resolves `proc-macro-crate` 3.5 and `serde_repr`'s `syn` 3 beside awl's own `toml` 0.8 and `syn` 2 — each recorded as one narrow, reasoned `deny.toml` skip with its removal condition.
- **The zero-network property is a design invariant, not an accident.** awl never phones home, never fetches at runtime (no telemetry, no remote font/dict/theme download, no update checker — see Check for Updates). Any future language pack is a file dropped into `fs::data_root()` or bundled at build time. `cargo deny`/`update`/`install` are build-time tooling and don't compromise this.

## Periodic code health

- **Run `scripts/coverage.sh` before risky waves and release preparation.** It is a pinned, local missing-law detector, not a percentage gate and not a normal-push CI job. Its ignored HTML/JSON reports and provenance record exactly what its LLVM instrumentation observed; CAPTURE.md documents the harness boundaries and the named platform exclusions. An uncovered path prompts contract review, never a shallow test written to improve a number.
