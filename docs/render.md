# awl docs — Render: adaptive column, theme caps, overlay chrome, picker rows

> Read before touching `render/`, `theme/model.rs` (RenderCaps), `overlay/`, `settings.rs` palette rows, or picker/row layout. Moved verbatim out of CLAUDE.md 2026-07-22 (queue item 17); earlier round history: `git log -p CLAUDE.md`.

## Adaptive-column placement (`render/geometry.rs`)

- On a small screen the symmetric centered column cramped the margin outline while the right margin sat empty. `TextPipeline::column_left` is the one owner of an adaptive policy (no config knob): shifts right under pressure to grant the outline a rail (taking the empty right-margin space), back to symmetric when there's room. Every downstream reader (caret/selection/washes, hit-test, drag handle, gutter) composes it for free.
- Pure policy `adaptive_column_left`, one formula `desired_left.min(max_left).max(symmetric_left)`, three regimes (wide = byte-identical passthrough to the old column; narrow = shift, width never touched; narrowest = re-centers → outline auto-hides at its existing floor). Hide threshold + shift threshold read the same `left` (can't drift). Transition is instant (glide banked). **Live-only:** the feel of a real small-screen resize.
- **THE CONTENT CLIP (item 84) — `TextPipeline::content_clip` / `clip_rects_to_band` (`render/rects.rs`).** The ONE resolved region every document-content, selection-adjacent quad must paint inside: horizontally the writing column ALWAYS (`column_left()`..`+column_width()` — the SAME box the diff-preview card draws at, so "the writing column" and "the active card" are one region), vertically the whole canvas on an ordinary frame narrowed to the diff panel's own inset band while a preview is up (`doc_clip_band`). A drag whose hit-test clamps to the page's own left edge, or a diff transcript scrolled so a selected/composing/caret row leaves the card, both resolve through this one rect — bounding PAINT only, never the SELECTABLE range. `range_rects` (feeding both `selection_rects` and `search_match_rects`), `preedit_rects`, and the caret's own park gate in `prepare_caret_layer` all route through it; on an ordinary frame this is a no-op (selection/caret x is already inside the column by construction — only the diff-panel vertical case genuinely trips it). Laws: `render/tests/selection_clip_law.rs` (a no-wildcard, by-name check that each emitter's own body calls the shared owner, plus the runtime proof the diff-panel case actually clips).
- **ITEM 84-FIX — the decorative-overhang emitters get their OWN Y-only clip, `clip_decorative_rects_to_band`, never `clip_rects_to_band`.** A follow-up audit found item 84 had ALSO routed `fence_panel_rects` and `code_pill_rects` — pre-existing DECORATIVE quads whose whole point is to overhang the bare glyph column (`FENCE_PANEL_INSET_X`/`CODE_PILL_INSET_X`, "so the panel reads as a distinct surface rather than being clipped exactly to the glyph edges") — through the strict writing-column X-clip meant for selection-adjacent quads. Invisible with page mode ON (the page pad dwarfs both insets); UNIVERSAL with page mode off (`text_pad()` is hard-zeroed then, so `text_left() == column_left()` and there is no margin to absorb the inset): every fenced block's panel clipped flush on both edges every frame, and an inline-code pill lost its left cap whenever the span touched column 0 or the wrap edge. Fix: two distinctly-named owners — `clip_rects_to_band` (X+Y, item 84's strict writing-column bound) stays SELECTION-ADJACENT-only (`range_rects`, `preedit_rects`; the caret gate reads `content_clip` directly); `clip_decorative_rects_to_band` (Y-only, the fn's pre-84 body, restored verbatim) is the DECORATIVE owner — `fence_panel_rects`, `code_pill_rects`, and the column-bound `wash_rects` comment/string/highlight buckets (structurally safe either way, kept on the decorative owner for one consistent story). Laws: `render/tests/washes.rs`'s `fence_panel_overhang_survives_content_clip_with_page_mode_off` / `code_pill_left_inset_survives_content_clip_at_line_start_with_page_mode_off` (each with a page-off zero-slack precondition, page mode off); the four `render/tests/selection_clip_law.rs` tests still hold unmodified — the selection/search/preedit/caret X-clip is untouched by this fix.

## Theme capabilities as data (`theme/model.rs::RenderCaps`)

- Render call sites never branch on world identity — they read a `RenderCaps` field: `selection_style`, `caret_block_style`, `backdrop`, `elevation`, `decorative_wash`, `image_reveal`, `highlight_texture`, plus the personality fields `card_anchor`, `chrome_face`, `motion`, `list_style`, `facet_style` (and `TitleStyle::Placard{corner,scale,ink}`). Born as the Wagtail refactor ("default = every other world"); that framing is dead — 16 worlds now, and many set fields away from default (Firetail: placard BL 4.5/Bold + `chrome_face` Named("Archivo Black") + Bordered elevation; Galah/Magpie/Mangrove/Firetail: `list_style` Bars + placards; five worlds TopLeft `card_anchor` (Cassowary + Mangrove now `TopRight` — the item-45 fable picks) while default flipped TopCenter; lava worlds `motion` calm). **No theme may need its own code path** — new personality = new caps field + data.
- **ITEM 70's PRINTED-CARD caps** (`card_texture: CardTexture::Flat|HalftoneDots{angle_deg,cell_px,density}`, `card_shape: CardShape::Rectangular|Chamfered{cut_px}`) — Quokka alone assigns `HalftoneDots` (+ `Chamfered`). Read by the ONE `ListBacking::Card` consumer (`render::chrome::TextPipeline::card_shape_texture`, called from `prepare_panel_card_elevation` + `overlay_draw_card`'s spell-popup arm): a plain `sd_round_rect` SDF (`shaders/selection.wgsl`) gets replaced by `sd_card_rect`'s CSG intersection with a diagonal half-plane when `chamfer > 0`, shared by the fill/border/shadow trio so the eight-edge boundary agrees across all three; the texture composites only over the FILL, sampled at the ABSOLUTE canvas pixel (not instance-local) so a Split Pane's two surfaces share one continuous phase across the open gap — Quokka's dot lattice with a pure horizontal rolloff (`halftone_rolloff`) keeping the left content column clear. The texture's own ink is DERIVED (`theme::card_texture_ink`, a `muted`→`base_300` blend) — never a raw/amber literal in the cap. `render::chrome::narrowed_chamfer_px` caps the chamfer at 40% of a card's own smaller dimension so a genuinely tiny surface (the spell popup) never lets the cut steal text room, while an ordinary short query bar stays untouched. Dev-only gallery knob `AWL_CARD_CAPS_FORCE=flat|halftone` (Quokka), mirroring `AWL_CJK_FORCE`'s "total no-op unless set" contract. (**Item 71** briefly extended this with a SECOND card texture, `CardTexture::JaggedWave{tiers,period_x,period_y,amplitude,density}` — Bowerbird's own woven printed-card identity, sharing `dot_color` with `HalftoneDots` via `SelectionPipeline::set_wave` — plus an `AWL_WAVE_FORCE` capture knob. **Item 86's light-worlds taste round retired the whole variant**: Bowerbird's summoned cards returned to plain flat, `JaggedWave` had zero remaining assignees, so it — and `set_wave`, `CardWave`, `CardTextureDraw`, the WGSL `jagged_wave_*` functions, and `AWL_WAVE_FORCE` — were all cut outright rather than left as dead code nothing constructs. `CardTextureDraw` (once a two-variant wrapper enum) collapsed back to a bare `Option<CardHalftone>`.)
- **ITEM 86's ZIGZAG margin ground, TILED INTO A FIELD BY ITEM 89** (`theme::Background::Zigzag{from,to,dir,tint,period_px,amplitude_px,angle,density}`, shader id 7) — a tiled field of repeating chevron ("V") rows over the gradient, in the SAME whisper-mark family as `Dots`/`Pinstripe`/`Starfield` (composites through the shared `pattern_coverage` → `fs_main` mix pipeline, unlike `Bands`/`Waves`' own final-color branch). Quokka's old dot grid and Gumtree's old grass-`Bands` field BOTH moved here, each with its OWN authored dials so the two never read as a recolor of one asset: `period_px` is the SCALE/SPACING dial (Quokka 50px, tight; Gumtree 190px, broad), `amplitude_px` the PROFILE dial (Quokka 10px, sharp; Gumtree 60px, a lazy meander — also derives the stroke's own thickness), `angle` the DIRECTION dial (Quokka ~54° steep diagonal; Gumtree ~15° near-horizontal), `density` the CONTRAST dial stacked on the shared `PATTERN_MAX_COVERAGE` ceiling (Quokka 0.60, bold; Gumtree 0.20, quiet). One shader function (`pattern_coverage`'s `shader == 7u` branch) reads all four via the SAME `params` vec4 slots Dots/Stripes/Bands already reuse per-shader (`params.x`=period, `.y`=angle, `.z`=amplitude, `.w`=density) — no new uniform layout, no per-world code path. `Background::Bands` is now DORMANT reusable infrastructure (Gumtree was its one assignee) — the exact "ships with zero worlds until one wants it" shape `edge: true` Dots already held. Laws: `render/tests/backgrounds_item86.rs` (the round's DESIGN brief — roster, four-dial distinctness, real-pixel contrast), `theme::tests`' data-level roster + palette laws. **ITEM 89 — the FIELD fix (correctness, not a new taste round).** The `shader == 7u` branch computed `center` from the ALONG-travel coordinate alone and took `abs(ry - center)`, which is ONE continuous chevron curve embedded in the plane: teeth repeated along travel, nothing repeated the curve ACROSS it, so a margin carried a single wandering stroke with large blank areas (62% of a tall Gumtree margin, the right two thirds of a Quokka one, measured at literally zero ink) and a taller window gained no second row — it only let the same stroke travel further off-canvas. The fix FOLDS the across-travel coordinate through the row period (`d = |fract((ry - center)/row_h + 0.5) - 0.5| * row_h`), turning the single curve into the family `center + k*row_h` — a genuinely tiled field. `row_h` IS `period_px` (a square lattice in the travel frame), so the SCALE dial now scales teeth and rows together: no fifth dial, no new uniform slot, no per-world code path. The amplitude is clamped in-shader to 40% of the period so neighbouring rows can never smear together (inert on both worlds' authored data, law-tested). Both worlds' dials were rescaled to the field — Quokka 100px/24px, Gumtree 250px/85px — giving ~3 broad chevron rows down an ordinary margin on Gumtree and ~6 tighter ones on Quokka; angles, tints, densities, cards, typography and every palette rung are untouched. The draw call is still the LITERAL `pass.draw(0..3, 0..1)` fullscreen triangle (three added fragment ALU ops; zero CPU work, zero new uniforms — per-frame cost is unchanged in kind). Laws: `render/tests/backgrounds_item89.rs` — an 18-cell (3x3 per margin, both margins, both worlds) real-pixel OCCUPANCY grid, a row-rhythm law, a height-scaling law (double the canvas, double the rows — the defect's signature inverted), zero mark ink inside the writing column, byte-determinism at two canvas sizes, the in-shader amplitude bound, a WGSL structural tripwire on the fold, and a non-vacuity self-proof that the grid rejects item 86's untiled stroke. All pixel claims are DIFFERENTIAL (the world as authored minus the same world with `density: 0.0`, so gradient + dither + quantization cancel exactly and the measurement is the mark alone) — `mark_field` is that oracle's one owner, reused by item 86's contrast law.
- `is_one_bit()` still exists (pins Wagtail's identity for the monochrome law tests) but the renderer no longer reads it. **Grep-law `theme_caps_law`:** fails if `.is_one_bit(` or a quoted world name appears in real code under `src/render/` — structurally bans a future per-theme special case.
- **Lava frost is an ORGANIC glyph-seeded FIELD (item 32), not rectangular pills.** The lava worlds (Mangrove + Firetail) keep both margins alive and frost the drawn margin ink (outline + gutter). Every visible margin glyph SEEDS a small close halo `[x0, x1, yc, r]`; the shader SUMS the halos into one continuous scalar field and thresholds it (`lava::frost_coverage`), so neighbours MERGE in any direction — nearby words/rows become one organic island, a group-gapped row separates, with NO per-row rule and NO zoom breakpoint (topology falls out of the continuous field). The ROW's radius ceiling is derived from the ZOOMED LABEL row height + the `feather_px` skirt (`render::frost_seed_radius`), and the skirt being a fixed logical px while the row scales with zoom is what lets islands join at small zoom and split at large zoom, naturally. Both worlds share the SAME shape/blur/dim/feather recipe (`crate::lava` consts); only the palette-derived colour differs (the world's own `Background::Lava` ground/blobs, via `render_caps.frost`). Owners: `TextPipeline::outline_frost_seeds` + `gutter_frost_seeds` → the shared `render::push_text_seeds` (per-glyph or the word-run degradation arm, `lava::FROST_SEED_PER_GLYPH`); the seed field is a PROTO-CACHE (`frost_seed_key` / `frost_seeds`, rebuilt only on a viewport/zoom/column/margin-text miss — witnessed by `--bench-frost`). All non-lava worlds stay byte-identical (empty seeds → inert shader path).
- **EACH SEED's own radius is PUNCTUATION-AWARE and BOUNDED, not a blanket row value (item 61).** The row's `frost_seed_radius` is a CEILING, not every run's literal radius: `render::frost_run_radius(r_row, run_ink_w, skirt)` takes the tightest of three — `r_row` itself, the run's OWN measured ink half-width (× `lava::FROST_RUN_INK_RADIUS_FRAC`) plus the skirt, and a BOUNDED END-PAD ceiling (`skirt × lava::FROST_END_RADIUS_SKIRTS`, independent of row height). An isotropic seed's `(1-(d/r)^2)^2` falloff is symmetric, so a near-zero-ink run at the FULL row-height radius reads as a bare circle hung off the glyph (an isolated `&`, a one-letter heading) instead of a close hug — the ink-derived bound ties that run's own radius to ITS OWN advance geometry instead. The end-pad ceiling separately caps how far a LONG single-run label's halo can reach past its own final glyph (a hyphenated compound like "Button-free" has no internal whitespace to break it into shorter runs) — a bound that does NOT grow with a taller row (a deep heading-ladder rung, a big zoom), only with the skirt. An ordinary multi-glyph run's ink half-width and the end-pad ceiling both already sit at or above `r_row` in practice, so `min()` is a no-op there — row/nearby-run merging for ordinary text is unchanged. No glyph or label is identity-matched; the bound is purely geometric. Laws: `render/tests/frost.rs`'s `isolated_punctuation_run_radius_is_bounded_below_a_normal_runs`, `long_run_end_pad_is_bounded_independent_of_row_height`, `nearby_ordinary_runs_still_merge_after_the_bounded_radius_round`.

## The caret's cell geometry (`render/caret.rs`)

- **THE INK BOX IS THE CARET'S ONE DESCRIPTION OF A LETTER (item 91).** `TextPipeline::caret_anchor_raster_box` is the single swash read on the caret path and returns the FULL placement box (`InkBox { left, top, width, height }`, plus the derived `descent()`); `caret_anchor_ink_box` layers the policy gate on it (no box on a MONO face, on a multi-char LIGATURE cluster, or on a glyphless / zero-mask anchor) and is the ONE funnel every ink-derived caret rule passes through. The horizontal half (the kerned-glyph fix) already rode it; item 91 added the vertical.
- **`caret_cell_vertical` OWNS the CELL caret's top and bottom** — `(center_y, height)` for the resting pose — and every cell-form caret reads it: the Block quad, Morph's fast-travel / ink-caret-world fold onto that quad (both via `caret_geometry`), and the glyphless SPACE BAR. Two arms behind the one funnel: the **ink box grown by `CARET_INK_PAD`** top and bottom on a proportional world, else the **row-scaled line cell** (`caret_block_h`) with the descender-aware bottom (`CARET_DESCENDER_PAD`) folded in. Descenders need no separate rule — `height - top` is already below the baseline in the same box. The BAR forms (I-beam, Morph's line-start degrade) deliberately stay line-box (`ibeam_bar_dims`): an insertion bar marks a boundary between glyphs, so it has no glyph to hug.
- **The bug it fixed was structural.** The bottom had a glyph-aware rule and the top did not, so the two edges could not agree: `CARET_BLOCK_H` is a fixed 0.8 fraction of the row centred on the line box, giving every letter the same top while the real ink top moves with the letter — measured on Gumtree/Literata at zoom 1, **8–9px of empty accent above `a`/`m`/`g`/`y`**, ~3px above `i`; after, a letter-independent 2–3px on all of them. The descender extension used to be re-derived at the draw site (`layers.rs::prepare_caret_block`) off the already motion-blended rect; folding it into the rest ENDPOINT is algebraically identical at settle 1 and lets `motion_geometry` blend it out mid-glide, so the travelling streak has exactly one thickness rule. Both ink corrections (x-shift and vertical re-centring) are scaled by the settle factor, so a moving caret is untouched.
- `CARET_INK_PAD` (3.0px at zoom 1) sits deliberately ABOVE `CARET_MORPH_DILATE_PX` (2.0): on a `CaretBlockStyle::Filled` world (Cassowary's CRT phosphor cursor) the block KNOCKS the glyph out with the morph silhouette dilated by that constant, so a pad at or below it would let the knockout eat the lit cell.
- Laws: `render/tests/caret_ink_box.rs` — the ink-box hug across ascender / x-height / descender with the pad asserted letter-INDEPENDENT (and the pre-fix gap asserted as a fixture witness), a no-wildcard `CaretMode::ALL` form sweep, the mono uniform-grid law (one top y at every column on Tawny + Mangrove), the moving-streak law, the glyphless space/EOL/line-start fallbacks, the pad-vs-dilation bound, and a grep-law that `render/layers.rs` holds no caret vertical geometry of its own.

## Picker hover/click stability + movement latency (`app/input/mouse.rs`, `overlay/nav.rs`, `probe.rs`)

- **THE REAL-MOTION HOVER GATE (item 85).** A theme-picker world jump previews the destination world's rail/size/type/material immediately (reanchor, Pane↔Bars, a settling font reshape) — but that re-layout must never itself read as a pointer gesture. `OverlayState::hover_at(px, py, hit)` is the ONE door `app/input/mouse.rs::overlay_hover` calls on every `CursorMoved` (real travel or a platform-synthesized duplicate at the identical coordinates): it compares `(px, py)` against `OverlayState::last_hover_px` and only re-hit-tests/re-selects (`hover_select`) when the pointer's own PHYSICAL position genuinely changed since the last check — a hit-test RESULT changing on its own, with the pixel unmoved, is a no-op. Pure and GPU-free (`hit` is a caller-supplied `Option<usize>`, not a pipeline call), so it's unit-tested directly. Laws: `overlay::tests::hover_at_gates_on_real_pointer_motion_not_a_relayout_hit_test_change` (proves BOTH that the hazard is real — an ungated `hover_select` really does cascade — and that the gate refuses it), `overlay::tests::hover_at_off_a_row_records_position_without_selecting`, `render::tests::overlay_hover_stability_law` (the same hazard against real pipeline geometry: a deliberate Wagtail→Cassowary rail crossing moves what a stationary pixel hits). Keyboard nav is untouched (`move_sel(±1)` still advances exactly one visible row per press, hover's own bookkeeping never leaks into it — `overlay::tests::keyboard_advances_exactly_one_visible_row_per_press_even_after_a_hover`).
- **THE ONE CLICK-ACTIVATION RULE.** `App::overlay_click` fires ONLY on `ElementState::Pressed` (never `Released`) and hit-tests `self.cursor_px` at that same instant — so "the row a click activates" is unconditionally the row under the PRESS, never a release position or whatever an earlier hover last computed. No separate release-time re-evaluation exists.
- **MOVEMENT-LATENCY, the live companion to offscreen `--bench-theme-burst` (item 85).** `App::retint_theme_preview` — the ONE owner every input kind (keyboard nav, mouse hover, mouse wheel) funnels a theme-picker world change through — arms `probe::mark_movement_input()` right before the real relayout work; `Gpu::redraw` closes it out against the frame it actually PRESENTS via `probe::note_presented_frame()`, at the exact point the existing `"present"` trace fires. `probe::latency_distribution()` reports count/min/p50/p95/max in ms. Reads through the SAME `probe::recording()` gate (both the automated `--live-script` probe and the user's `AWL_FLIGHT_RECORDER`) every other diagnostic trace point uses — no new shared live/headless driver. Surfaced two ways: the script grammar's `latency` step (prints one `LIVE-PROBE latency …` stdout line, the `shot` line's protocol twin) and, for the flight recorder, one closing `movement-latency distribution: …` trace line at app teardown. Native-only; a no-op on a plain launch (the clock is never even read). Laws: `probe::tests::movement_latency_mark_and_present_produce_a_sample_and_distribution`, `probe::tests::movement_latency_is_a_no_op_outside_recording`, `probe::tests::parse_covers_the_latency_step`. The distribution's TIMING/feel over real time is live-only by nature (CLAUDE.md) — the user remains the oracle for felt lag; this instruments the same real end-to-end path (dispatch → relayout → encode/submit → compositor present) `--bench-theme-burst` cannot reach offscreen.
