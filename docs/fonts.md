# awl docs — Fonts: display faces, per-world mono, CJK

> Read before touching font selection in `render.rs`, `script.rs`, `frontmatter.rs`, `theme::FontId`/ladders, or bundled font assets. Moved verbatim out of CLAUDE.md 2026-07-22 (queue item 17); earlier round history: `git log -p CLAUDE.md`.

## Fonts (`render.rs`) — display face, per-world mono, per-script CJK

- **Display face:** each world names an embedded family (`Theme::font`), shaped via `Family::Name`.
- **Tripwire: the IBM Plex Mono Weight-300 trap:** it ships as Light (Weight 300); cosmic-text's fallback keeps only `weight_diff == 0` faces before name-matching, so a default-400 request drops it and mono worlds fall through to proportional `.SF NS`. `mono_safe_weight()` requests Weight 300 for `"IBM Plex Mono"`. Test: `mono_world_shapes_uniform_pitch`.
- **Face PITCH is measured, not named (`render/facepitch.rs`, item 97):** "is this family monospaced?" — the question the caret's uniform-grid vs ink-box fork asks (`caret::font_is_mono`) — is answered by reading the face's OWN advance widths over a probe glyph set (`PITCH_PROBE`) through **skrifa**, the font stack cosmic-text already shapes with; family names come from fontdb, so the key is exactly the string a `Theme::font` names. It was a literal three-name match, which had already lost Monaspace Xenon and JetBrains Mono once and never had **Iosevka** — so Currawong and Cassowary drew the proportional ink-hugging caret (a 5px top wobble letter to letter) instead of the grid. The Plex-Light trap above cannot reach this path: nothing here SELECTS a face out of a populated DB, each file is parsed and measured alone, so there is no weight request to mismatch. Membership is sweepable two ways: `FONT_THEME_FACES` pairs every `include_bytes!` with a `Pitch`, so a new face cannot COMPILE without a conscious call, and `render::tests::facepitch` pins declaration against measurement, the roster against `theme::THEMES`, and the bold companions against their Regulars. Pixel law: `tests/caret_mono_grid_pixels.rs`.
- **The SAME per-face pass also measures a TYPICAL-LETTER RATIO (`facepitch::typical_letter_ratio`, item 105):** the mean of the face's own x-height and cap-height, each ÷ its ascent, read via the SAME skrifa `metrics()` call over the SAME bundled bytes `measure_pitch` already parses (one pass, two facts). Feeds the caret's PROPORTIONAL-fallback synthetic ink box (`caret::TextPipeline::caret_synthetic_ink_box`, docs/render.md) — never a real glyph's own ink, only the glyphless/EOL/space case where there is no letter to sample. A face with neither metric (rare symbol/geometric faces) falls back to a fixed constant (`DEFAULT_TYPICAL_LETTER_RATIO`), the same "measured, with a documented floor" shape `measure_pitch`'s `None` already has.
- **Per-world code mono (`Theme::mono`):** a code buffer (`syntax_lang().is_some()`) shapes in `Theme::mono`; prose/markdown/scratch keep `Theme::font`. Prose stays byte-identical — only code buffers change.
- **CJK / i18n (per-script resolution ladder):**
  - **`theme::FontId {Latin, Ja, ZhHans, ZhHant, Ko}`** + `Theme::candidates(id)` (a prioritized family ladder, data not code). `resolve_font_id` walks the ladder → first registered family + its weight nearest 400 (the Hiragino/PingFang weight-trap correction).
  - **Never-tofu law:** every world has a non-empty ladder for every script (structural test) and Latin/Ja/ZhHans/Ko always resolve to an embedded face (font-DB test).
  - **Bundled floors** (all OFL, subset from Google Fonts variable instances at wght=400): Noto Serif/Sans JP, Noto Serif/Sans SC (zh-Hans, GB 2312 subset), Noto Sans KR + Gowun Batang (ko serif split), LXGW WenKai (characterful Klee-world zh-Hans). `ZhHant` is system-only (Big5 coverage banked). Declined for cause: KingHwa OldSong (no-derivatives license), GenSenRounded (TW-only, wrong for zh-Hans).
  - **`script.rs`** classifies runs (Kana/Hangul/Bopomofo/Han) and resolves each run's `FontId` independently: doc's frontmatter `lang:` tag → the run's own script → `cjk_priority` tiebreak (Han is ambiguous) → Latin floor. `add_script_spans` (render/spans.rs) overrides family+weight per run, resolved once per reshape.
  - **Frontmatter (`frontmatter.rs`):** a strict `---` block at byte 0, reads `lang:` (BCP 47). Excluded from word-count / spell / nits. Renders dim, WYSIWYG block-scoped conceal (reuses the Fence rule).
  - **Write-back-once (live-app only):** opening an untagged markdown CJK doc stamps `---\nlang: ..\n---` as a normal undoable edit (never a silent disk write), markdown buffers only, never re-tagged. Config `cjk_priority` (default `["ja","zh-Hans","zh-Hant","ko"]`) is the Han tiebreak.
  - **Dev knob:** `AWL_CJK_FORCE=system|bundled|floor` (env, CLI-invisible, no-op unless set) prunes families for the A/B galleries (`gallery/*`, gitignored). Sidecar `doc_lang` + `font.scripts`/`font.cjk` (`{family,bundled}`).
- **Quokka's printed-card display face (item 70):** Sour Gummy (OFL 1.1, google/fonts `ofl/sourgummy`), instanced at `wght=400/700/900 wdth=100` from the variable source, Latin+punctuation subset (335 codepoints, matching Literata/Newsreader's fuller prose coverage — see `assets/fonts/LICENSES.md` for the provenance + the 21-codepoint documented upstream gap). The 700 file is the real `**bold**`/heading companion (`FONT_THEME_BOLD_FACES`, same family "Sour Gummy"); the bundled 900 file stays addressable-but-unselected — `AWL_SOURGUMMY_HEAVY_FORCE=900` (mirrors `AWL_CJK_FORCE`'s dev-knob contract) prunes the 700 face so `Weight::BOLD` falls through to it instead, for the round's 700-vs-900 taste gallery.
- **Kite's display face is the already-bundled Fira Sans pair (item 132).** `FiraSans-Regular.ttf` (274,832 bytes) and `FiraSans-Bold.ttf` (191,756 bytes) were embedded, licensed and attributed long before Kite — they were Quokka's face until item 70 moved it to Sour Gummy, and were the roster's last registered-but-UNASSIGNED display family. Both are SIL OFL 1.1 with NO reserved font name, taken from the face's own embedded `name` table (`assets/fonts/LICENSES.md`'s ground-truth rule), sourced from `github.com/google/fonts/tree/main/ofl/firasans`. So the twentieth world adds **zero font bytes**, zero new license surface and zero new audit rows. The pick is on merit as well as thrift: Fira Sans is Mozilla's screen-engineered UI sans (low contrast, upright, narrow terminals), which is the technical register Kite wants, and its lowercase `l` is a BARE STEM — the one class the app-icon law says can wear any of the three logo-cursor presets.
- **Theme-preview debounce — LEADING EDGE plus TRAILING COALESCE (item 202 repair round).** A preview always re-tints colors instantly (`retint_theme_preview`, O(1)). The font reshape used to be governed by ONE flat window trying to answer two different questions at once: item 37b measured the reshape's real cost as sub-frame-cheap and dropped the window to 0, which instead made `debounce_due`'s `now - dirty >= window` trivially true at elapsed 0 — every single preview step (keyboard, pointer hover, wheel; all three share `retint_theme_preview`) reshaped SYNCHRONOUSLY inside the very `about_to_wait` pass that armed it, so a rapid run of steps queued behind each other on the main thread (measured live: a 30ms-apart six-step burst produced 6 separate reshapes, p95 movement-latency 18.9ms). Item 202's first landing raised the flat window to 100ms, which coalesced the burst (one reshape, not six — p50 5.1ms / p95 8.9ms) but punished an ISOLATED single step too (settle ~124ms, reopening the "felt theme-switch freeze" 37b's own commit was about) — proof that the reshape genuinely is NOT sub-frame-cheap in general (`--bench-theme-burst` measures 10-35ms depending on document size, flat whether loaded or not), so 37b's characterization of its own 29-32ms figure was wrong from the day it was written, not something that later expired.
  - The actual fix is a different RULE, not a different number: `theme_font_reshape_decision` (`app.rs`) is ISOLATED (reshape now) when nothing has reshaped in the last `theme_font_debounce()` window and nothing is already pending — item 37b's own ~39ms single-step path, untouched. A step arriving WITHIN that window of the last reshape (or while one is already pending) is a BURST CONTINUATION and coalesces into the trailing debounce instead — so an N-step burst pays one leading reshape (its first step) plus one trailing settle (once it stops), never N and never the isolated case's cost either. `App::theme_font_last_reshape_at` is the leading edge's own clock (stamped by an immediate reshape, a commit/revert, or a coalesced settle firing); `App::theme_font_at` stays the pending/sliding trailing mark, unchanged in shape.
  - `AWL_THEME_FONT_DEBOUNCE_MS` governs BOTH halves of the window (leading-edge cooldown and trailing coalesce) and remains the A/B escape hatch: unset/default (100ms) is the leading+trailing fix; an explicit `0` degenerates back to the pre-202 defect exactly (every step reads "isolated" — `0 >= 0` is trivially true — so every step reshapes again), useful only for A/B regression comparison, never a recommended setting. Enter/Esc retint synchronously + cancel the deferral. Headless applies fonts synchronously (captures unchanged).
- **ITEM 241 — THE LEADING-EDGE TEST NOW READS THE WORK, NOT THE CLOCK ALONE.** Item 202's rule still asked "should this step wait?" from elapsed time by itself, against a cost model that was a CONSTANT calibrated when an isolated reshape cost ~39ms. **It is not a constant.** `--bench-theme-burst` (release, same machine, 2026-08-03) times one `sync_theme_font` at **0.2ms** on a seven-line document, **12.0ms** on CLAUDE.md and **24.4ms** on the 1896-line `long_bullets.md` fixture — a hundredfold spread the window cannot see. On the cheap end the arithmetic was absurd: a user arrowing **Kite→Mulga** measured `theme latest 103.6 ms · theme worst 117.2 ms` over a breakdown summing to **2.1ms**.
  - **The discriminator, run live before anything was changed** (`--live-script`, release, `--debug` HUD, screen re-checked unlocked at both ends of every run; 30ms-apart nine-step burst, same pair): the headline tracks `AWL_THEME_FONT_DEBOUNCE_MS` **one-for-one** — `0` → no transaction recorded at all, `50` → **64.1ms**, `100` → **105.4ms**, `250` → **262.1ms** — while the work phases never leave ~5ms. The same burst from **Tawny** (a quiet static world, no `Background::WarpedGrid`) measured **105.8ms**, so nothing about the residual was Kite's travelling ground. The residual was the debounce, entirely.
  - **The rule:** `theme_font_reshape_decision` takes `last_reshape_cost` beside its clock. A reshape measured cheaper than `THEME_FONT_CHEAP_RESHAPE_MS` (**4ms** — the empty middle of the measured spread, and a quarter of a 60Hz frame) reads ISOLATED however recently it happened; anything dearer, or **anything unmeasured (`None`)**, keeps item 202's elapsed-time rule exactly. Silence is never read as cheap. The cost comes from the same `sync_theme_font_timed` door **every live reshape now runs through** — measuring it is no longer a debug-mode diagnostic, because the scheduler needs it (the plain `sync_theme_font` is still the headless path's only variant, so a capture touches no `Instant`).
  - **Item 202's coalescing is intact where it was built for.** Live, same burst over the 1896-line fixture: `theme latest 143.0 ms` with `wait 101.1 · reshape 27.2` — one leading reshape plus one trailing settle, the trailing window fully paid because a 27ms reshape is worth deferring. `--bench-theme-burst`'s reshape-count witness is untouched (the bench drives `TextPipeline` directly and never consults this rule).
  - **Live before → after, release, same HUD.** Kite→Mulga 30ms burst **105.4 → 10.8ms** (worst 14.0); Tawny→Mulga 30ms burst **105.8 → 13.9ms**; Kite→Mulga isolated 250ms-apart steps **no readout at all → 10.1ms** (worst 12.9). Movement-latency distributions across the change did not regress on the burst arm (Kite p50 8.8→9.9, p95 20.6→13.9; Tawny p50 9.5→10.2, p95 13.6→13.9) — N cheap reshapes cost nothing measurable, which is the premise the gate rests on. On the big document the isolated arm now measures **44.4ms** (worst 48.2), matching item 37b's own ~39ms figure for the first time since it was written.
  - **The instrument was blind in a second way, and it is fixed too** (`src/themeswitch.rs`): `retint_theme_preview`'s IMMEDIATE arm ran the untimed `sync_theme_font()` and armed no transaction, so the settle readout could ONLY ever report a coalesced settle — the one path that includes a deliberate wait. A genuinely isolated arrow run drew **no theme lines at all**. Both arms are measured now, `SwitchPhase` gained `Wait`/`Schedule`/`Acquire` to name the three segments nothing timed, and `MIN_PHASE_COVERAGE` makes any future gap self-reporting (`unaccounted N.N` in the breakdown itself). Live coverage after: 100% on every arm measured.
