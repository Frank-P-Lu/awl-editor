# awl docs — Fonts: display faces, per-world mono, CJK

> Read before touching font selection in `render.rs`, `script.rs`, `frontmatter.rs`, `theme::FontId`/ladders, or bundled font assets.

## Fonts (`render.rs`) — display face, per-world mono, per-script CJK

- **Display face:** each world names an embedded family (`Theme::font`), shaped via `Family::Name`.
- **Tripwire: the IBM Plex Mono Weight-300 trap:** it ships as Light (Weight 300); cosmic-text's fallback keeps only `weight_diff == 0` faces before name-matching, so a default-400 request drops it and mono worlds fall through to proportional `.SF NS`. `mono_safe_weight()` requests Weight 300 for `"IBM Plex Mono"`. Test: `mono_world_shapes_uniform_pitch`.
- **Face PITCH is measured, not named (`render/facepitch.rs`):** "is this family monospaced?" — the question the caret's uniform-grid vs ink-box fork asks (`caret::font_is_mono`) — is answered by reading the face's OWN advance widths over a probe glyph set (`PITCH_PROBE`) through **skrifa**, the font stack cosmic-text already shapes with; family names come from fontdb, so the key is exactly the string a `Theme::font` names. It was a literal three-name match, which had already lost Monaspace Xenon and JetBrains Mono once and never had **Iosevka** — so Currawong and Cassowary drew the proportional ink-hugging caret (a 5px top wobble letter to letter) instead of the grid. The Plex-Light trap above cannot reach this path: nothing here SELECTS a face out of a populated DB, each file is parsed and measured alone, so there is no weight request to mismatch. Membership is sweepable two ways: `FONT_THEME_FACES` pairs every `include_bytes!` with a `Pitch`, so a new face cannot COMPILE without a conscious call, and `render::tests::facepitch` pins declaration against measurement, the roster against `theme::THEMES`, and the bold companions against their Regulars. Pixel law: `tests/caret_mono_grid_pixels.rs`.
- **The SAME per-face pass also measures a TYPICAL-LETTER RATIO (`facepitch::typical_letter_ratio`):** the mean of the face's own x-height and cap-height, each ÷ its ascent, read via the SAME skrifa `metrics()` call over the SAME bundled bytes `measure_pitch` already parses (one pass, two facts). Feeds the caret's PROPORTIONAL-fallback synthetic ink box (`caret::TextPipeline::caret_synthetic_ink_box`, docs/render.md) — never a real glyph's own ink, only the glyphless/EOL/space case where there is no letter to sample. A face with neither metric (rare symbol/geometric faces) falls back to a fixed constant (`DEFAULT_TYPICAL_LETTER_RATIO`), the same "measured, with a documented floor" shape `measure_pitch`'s `None` already has.
- **Per-world code mono (`Theme::mono`):** a code buffer (`syntax_lang().is_some()`) shapes in `Theme::mono`; prose/markdown/scratch keep `Theme::font`. Prose stays byte-identical — only code buffers change.
- **CJK / i18n (per-script resolution ladder):**
  - **`theme::FontId {Latin, Ja, ZhHans, ZhHant, Ko}`** + `Theme::candidates(id)` (a prioritized family ladder, data not code). `resolve_font_id` walks the ladder → first registered family + its weight nearest 400 (the Hiragino/PingFang weight-trap correction).
  - **The cell caret follows that resolved script face without following an individual glyph.** `bundled_cjk_faces` is the font-loader roster; `facepitch::ideographic_cell_em` reads each face's OS/2 typographic ascender/descender as a baseline split normalised to one em. A proportional document's cell-form caret uses that stable face cell at a classified CJK anchor, padded by the existing authored caret pad. Latin remains on its typical-letter rule, mono documents remain on their line cell, and neighbouring kanji never acquire per-glyph height jitter.
  - **Never-tofu law:** every world has a non-empty ladder for every script (structural test) and Latin/Ja/ZhHans/Ko always resolve to an embedded face (font-DB test).
  - **Bundled floors** (all OFL, subset from Google Fonts variable instances at wght=400): Noto Serif/Sans JP, Noto Serif/Sans SC (zh-Hans, GB 2312 subset), Noto Sans KR + Gowun Batang (ko serif split), LXGW WenKai (characterful Klee-world zh-Hans). `ZhHant` is system-only (Big5 coverage banked). Declined for cause: KingHwa OldSong (no-derivatives license), GenSenRounded (TW-only, wrong for zh-Hans).
  - **PDF Japanese fallback stays closed and portable.** Latin glyphs keep the Bitter/IBM Plex faces. Japanese script and punctuation missing from those faces use the bundled Noto Serif JP for prose and headings, and Noto Sans JP for code. The regular Japanese faces receive a restrained PDF text stroke when the source style is bold. Only used faces and glyph outlines are embedded; system fonts and network lookup never participate.
  - **`script.rs`** classifies runs (Kana/Hangul/Bopomofo/Han) and resolves each run's `FontId` independently: doc's frontmatter `lang:` tag → the run's own script → `cjk_priority` tiebreak (Han is ambiguous) → Latin floor. `add_script_spans` (render/spans.rs) overrides family+weight per run, resolved once per reshape.
  - **Frontmatter (`frontmatter.rs`):** a strict `---` block at byte 0, reads `lang:` (BCP 47). Excluded from word-count / spell / nits. Renders dim, WYSIWYG block-scoped conceal (reuses the Fence rule).
  - **Tagging is EXPLICIT — opening a document never edits it.** The `lang:` block is written by exactly one door, the palette's **"Tag document language"** (`Action::TagDocumentLanguage` → `actions::edit::tag_document_language`, `Format` family, no default chord): it stamps `---\nlang: ..\n---` at byte 0 as one undoable edit, and is a calm no-op on a non-markdown buffer, on a document that already carries a frontmatter block, and on a document with no CJK in it. Detection is in-memory and per-open: `dominant_cjk` reads the buffer, and nothing has to be written for resolution to work. Config `cjk_priority` (default `["ja","zh-Hans","zh-Hant","ko"]`) is the Han tiebreak — the palette command reads the LIVE ladder (`frontmatter::cjk_priority()`, the one the Settings row shows and the CJK picker promotes); the render ladder reads `Config::cjk_priority_or_default`.
  - **Why the automatic stamp was retired.** It ran on every fresh open (the launch argument and `load_path` alike), so opening a note to read it edited it, and the ordinary autosave engine then wrote that edit into the user's file. Worse, a tag WINS the resolution ladder: a `lang: ja` stamped onto a kana-bearing note made its ambiguous Han runs resolve Japanese permanently, outranking the `cjk_priority` the user had explicitly set (reported symptom — 你好 in a Japanese-dominant note rendering with a Japanese face despite a Chinese tiebreak). Precedence itself is unchanged and deliberately so: a tag in the file still wins, which is what makes a tagged document portable. Laws: `app::tests::files::opening_an_untagged_cjk_document_never_mutates_the_buffer` (sweeps every `dominant_cjk` script across both open doors, and asserts the on-disk bytes after an autosave flush), `an_untagged_cjk_document_keeps_the_configured_han_tiebreak`, and `actions::tests::format_editing`'s three `tag_document_language_*` tests.
  - **Dev knob:** `AWL_CJK_FORCE=system|bundled|floor` (env, CLI-invisible, no-op unless set) prunes families for the A/B galleries (`gallery/*`, gitignored). Sidecar `doc_lang` + `font.scripts`/`font.cjk` (`{family,bundled}`).
- **Quokka's printed-card display face:** Sour Gummy (OFL 1.1, google/fonts `ofl/sourgummy`), instanced at `wght=400/700/900 wdth=100` from the variable source, Latin+punctuation subset (335 codepoints, matching Literata/Newsreader's fuller prose coverage — see `assets/fonts/LICENSES.md` for the provenance + the 21-codepoint documented upstream gap). The 700 file is the real `**bold**`/heading companion (`FONT_THEME_BOLD_FACES`, same family "Sour Gummy"); the bundled 900 file stays addressable-but-unselected — `AWL_SOURGUMMY_HEAVY_FORCE=900` (mirrors `AWL_CJK_FORCE`'s dev-knob contract) prunes the 700 face so `Weight::BOLD` falls through to it instead, for the 700-vs-900 taste gallery.
- **Kite's display face is the already-bundled Fira Sans pair.** `FiraSans-Regular.ttf` (274,832 bytes) and `FiraSans-Bold.ttf` (191,756 bytes) were embedded, licensed and attributed long before Kite, and were the roster's last registered-but-UNASSIGNED display family. Both are SIL OFL 1.1 with NO reserved font name, taken from the face's own embedded `name` table (`assets/fonts/LICENSES.md`'s ground-truth rule), sourced from `github.com/google/fonts/tree/main/ofl/firasans`. So the twentieth world adds **zero font bytes**, zero new license surface and zero new audit rows. The pick is on merit as well as thrift: Fira Sans is Mozilla's screen-engineered UI sans (low contrast, upright, narrow terminals), which is the technical register Kite wants, and its lowercase `l` is a BARE STEM — the one class the app-icon law says can wear any of the three logo-cursor presets.
- **Theme-preview visible shaping is unconditional; only the off-screen tail coalesces.** A preview re-tints colors instantly and reshapes every row its next frame can paint when the active world's effective face (or, for a buffer that bakes per-span colors, its palette) differs from the document's shaped state (`retint_theme_preview` → `App::sync_theme_font_measured` → `TextPipeline::needs_theme_reshape`). Rapid previews replace the incomplete off-screen tail; the existing crossing quiet-settle finishes the final highlighted world once. Commit and revert settle synchronously. There is no input rate limiter, background shaping thread, per-theme document cache, or second renderer.
  - **Why it was removed:** the mechanism's own mode boundary sat inside human key cadence, not outside it. At the 100ms window, the arm sequence per cadence (`I`mmediate / `C`oalesce) read `ICCCC…` with a 141–151ms stall at a 60–95ms/step cadence, `IIIICCCC` at 100ms/step, and all-`I` at ≥105ms/step — a ~4× latency gap decided by ordinary jitter in the user's own typing rhythm, not by anything the mechanism could see. Coalescing also manufactured work of its own: a 12-hop preview needing only 8 real reshapes reported 12 in a coalesced burst. Raising the window instead of removing it was tried and refuted, not merely left untried: 300ms gave a 348ms settle, 400ms gave 459ms — p50 improved while the FELT settle degraded 8–10×, because colour-only steps present fast and get sampled while stalled ones don't.
  - **The cost this trades away is real, and it was measured with `--bench-theme-burst` (release), not assumed.** A 9-step burst through 9 worlds that each change display face (the bench's own `BURST_WORLDS` roster — "exactly what arrowing through the faceted picker does") totals, colors-plus-frame plus the one deferred settle, **~75ms on CLAUDE.md (119 lines) and ~83ms on the 1896-line `long_bullets.md`** under the removed debounce. The same 9-step burst under item 290's unconditional reshape (the bench's "eager preview" section, `sync_theme` + frame per step, summed) totals **~298ms on CLAUDE.md and ~381ms on `long_bullets.md`** — roughly a **4×** regression in raw main-thread work for this worst-case "every hop changes face" pattern, not the 12.3ms/n=1 figure once quoted for it (that figure carries item 291's own measurement bias — `probe::mark_movement_input` overwrites a pending mark, so a multi-step burst reports as a single sample — and undercounts a real burst by roughly two orders of magnitude). Each INDIVIDUAL step's cost (~20–30ms on these fixtures) is unchanged and still matches item 37b's own ~39ms isolated-step figure; what changed is that a burst now pays that cost once per step instead of once per burst. Whether this trade is worth it is a live-feel call — flagged for human confirmation, not decided here.
  - **What survives.** The color/font split (`TextPipeline::sync_theme_colors` vs `sync_theme_font`) stays — a preview still re-tints instantly and only reshapes when `needs_theme_reshape` says there is real work. The settle-transaction readout (`src/themeswitch.rs`) also stays. Its first-present timing remains per highlighted world; the coalesced tail is deliberately outside that visible-latency figure.
