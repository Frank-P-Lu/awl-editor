# Grounds and render capabilities

Read before changing RenderCaps, background shaders, coordinate spaces, or lava frost.

[Guide](../render.md) · Paths in code examples are relative to the repo root.

## Theme capabilities as data (`theme/model.rs::RenderCaps`)

- Render call sites never branch on world identity — they read authored `RenderCaps` expressions. `selection_style` and `caret_block_style` may each choose an independent `TwoColour` palette-role pair; one shared subtractive renderer swaps any pair, so black/white is not baked into the path. No-variation facts do not occupy theme data: overlay motion defaults to `MotionJuice::CALM`, Pane defaults to `PaneSplit::Split`, lava frost reads the shared `crate::lava` recipe, and `selection_ui` always derives from the surface ramp. Test-only overrides retain the dormant motion and Pane axes for mutation laws. The roster census reports every zero/single-adopter field by name and rejects any new unclassified field. Sparse authored expressions — Ruled, Diagonal directions, chamfer, ambient stars, icon-ground presets and background kinds — remain data. **No theme may need its own code path.**
- **ITEM 70's PRINTED-CARD caps** (`card_texture: CardTexture::Flat|HalftoneDots{angle_deg,cell_px,density}`, `card_shape: CardShape::Rectangular|Chamfered{top_cut_px,bottom_cut_px}`) — Quokka and Cassowary assign `Chamfered` (Quokka alone also assigns `HalftoneDots`). Read by the ONE corner-mask owner (`render::chrome::TextPipeline::card_shape_texture`, called from `prepare_panel_card_elevation`, `overlay_draw_card`'s spell-popup arm, and `overlay_material.rs`'s scanline/placard materials — every console layer that draws a card-shaped quad resolves ITS OWN rect through this same function rather than deciding its corner independently): a plain `sd_round_rect` SDF (`shaders/selection.wgsl`) gets replaced by `sd_card_rect`'s CSG intersection with a diagonal half-plane, picked PER-HALF by the fragment's own `p.y` sign (`chamfer_top` above the card's own center, `chamfer_bottom` below), shared by the fill/border pair so the eight-edge boundary agrees across both; the texture composites only over the FILL, sampled at the ABSOLUTE canvas pixel (not instance-local) so a Split Pane's two surfaces share one continuous phase across the open gap — Quokka's dot lattice with a pure horizontal rolloff (`halftone_rolloff`) keeping the left content column clear. The texture's own ink is DERIVED (`theme::card_texture_ink`, a `muted`→`base_300` blend) — never a raw/amber literal in the cap. `render::chrome::narrowed_chamfer_px` caps EACH half's chamfer at 40% of a card's own smaller dimension so a genuinely tiny surface (the spell popup) never lets the cut steal text room, while an ordinary short query bar stays untouched. Dev-only gallery knob `AWL_CARD_CAPS_FORCE=flat|halftone` (Quokka), mirroring `AWL_CJK_FORCE`'s "total no-op unless set" contract. (**Item 71** briefly extended this with a SECOND card texture, `CardTexture::JaggedWave{tiers,period_x,period_y,amplitude,density}` — Bowerbird's own woven printed-card identity, sharing `dot_color` with `HalftoneDots` via `SelectionPipeline::set_wave` — plus an `AWL_WAVE_FORCE` capture knob. **Item 86's light-worlds taste round retired the whole variant**: Bowerbird's summoned cards returned to plain flat, `JaggedWave` had zero remaining assignees, so it — and `set_wave`, `CardWave`, `CardTextureDraw`, the WGSL `jagged_wave_*` functions, and `AWL_WAVE_FORCE` — were all cut outright rather than left as dead code nothing constructs. `CardTextureDraw` (once a two-variant wrapper enum) collapsed back to a bare `Option<CardHalftone>`.) **Item 471** split the one `chamfer`/`cut_px` into a top/bottom pair so Cassowary's docked seam edge (the facet strip's TOP band) can go square (`top_cut_px: 0.0`) while its free bottom edge keeps the cut (`bottom_cut_px: 11.0`) — Quokka carries the same value on both halves, its pre-existing all-four-corner look byte-identical. The std140 `Globals::chamfer_top`/`chamfer_bottom` pair replaces the single field (`_pad2` shrinks from a `vec2` to one `f32` to keep the struct's total size unchanged — see that struct's own doc for the byte math); `SelectionPipeline::set_chamfer` takes both. The round's real fix was less the new axis than the OWNERSHIP: `overlay_material.rs` used to hardcode the placard's chamfer to `0.0` regardless of the card's real shape (a per-layer opinion independent of the card it bleeds against, the square-artifact bug's actual cause) — it now resolves through `card_shape_texture` against its OWN rect like every other layer, and `SelectionPipeline::chamfer()` (test-only) lets a law assert every layer agrees with the owner instead of trusting the call sites by convention.
- **ITEM 86's ZIGZAG margin ground, TILED INTO A FIELD BY ITEM 89** (`theme::Background::Zigzag{from,to,dir,tint,period_px,amplitude_px,angle,density}`, shader id 7) — a tiled field of repeating chevron ("V") rows over the gradient, in the SAME whisper-mark family as `Dots`/`Pinstripe` (composites through the shared `pattern_coverage` → `fs_main` mix pipeline, unlike `Bands`/`Waves`' own final-color branch). Quokka's old dot grid and Gumtree's old grass-`Bands` field BOTH moved here, each with its OWN authored dials so the two never read as a recolor of one asset: `period_px` is the TOOTH-WAVELENGTH dial (Quokka 100px, tight; Gumtree 170px, broad), `amplitude_px` the PROFILE dial (Quokka 24px; Gumtree 60px — and, through item 89's abutment rule, the field's ROW PITCH and the stroke's own thickness), `angle` the DIRECTION dial (Quokka ~54° steep diagonal; Gumtree ~15° near-horizontal), `density` the CONTRAST dial stacked on the shared `PATTERN_MAX_COVERAGE` ceiling (Quokka 0.60, bold; Gumtree 0.20, quiet). One shader function (`pattern_coverage`'s `shader == 7u` branch) reads all four via the SAME `params` vec4 slots Dots/Stripes/Bands already reuse per-shader (`params.x`=period, `.y`=angle, `.z`=amplitude, `.w`=density) — no new uniform layout, no per-world code path. `Background::Bands` is now DORMANT reusable infrastructure (Gumtree was its one assignee) — the exact "ships with zero worlds until one wants it" shape `edge: true` Dots already held. Laws: `render/tests/zigzag_ground.rs` (the round's DESIGN brief — roster, four-dial distinctness, real-pixel contrast), `theme::tests`' data-level roster + palette laws. **ITEM 89 — the FIELD fix (correctness, not a new taste round), in TWO parts.** *(a) The FOLD.* The `shader == 7u` branch computed `center` from the ALONG-travel coordinate alone and took `abs(ry - center)`, which is ONE continuous chevron curve embedded in the plane: teeth repeated along travel, nothing repeated the curve ACROSS it, so a margin carried a single wandering stroke with large blank areas (62% of a tall Gumtree margin, the right two thirds of a Quokka one, measured at literally zero ink) and a taller window gained no second row — it only let the same stroke travel further off-canvas. The fix FOLDS the across-travel coordinate through a row pitch (`d = |fract((ry - center)/row_h + 0.5) - 0.5| * row_h`), turning the single curve into the family `center + k*row_h` — a genuinely tiled field. *(b) The ABUTMENT RULE — the coverage repair.* The fold's first cut set `row_h = period_px` (a square lattice). That TILES but does not COVER: row `k`'s ribbon only ever visits `ry` in `[k*row_h - amp - t, k*row_h + amp + t]`, so whenever `2*amp + 2*t < period_px` the field carries a hard BLANK LANE of `period_px - 2*amp - 2*t` that no chevron enters at any point of the plane — ~70px every 250px on the dials that first shipped, and at ordinary-but-shorter windows a narrow margin could sit wholly inside one (verified at the app's real adaptive column geometry: an 80x182px band of a 1600x600 Gumtree right margin, and a 27x234px cell of a 1400x700 left margin, at exactly zero deviation; Quokka's finer field was clean at every size). `row_h` is now `2.0*amp + thickness` (`theme::Background::zigzag_row_pitch_px` is the host mirror), so each row's ribbon sweeps exactly its own lane and its CORE sweeps a lane plus `0.2*t` of overlap: rows ABUT for ANY dials at any angle — coverage stopped being a property of the dial pair and became a property of the shader. (**Item 100** corrected that claim's scope: it read "any viewport size or aspect" and that clause was false — a viewport is a ROTATED RECTANGLE of the plane, so it inherits the guarantee only while it holds a whole tooth of travel; a `period_px: 2000`/`amplitude_px: 150` field on a 1200x800 canvas leaves a measured 78px lane. Bounded by the TOOTH, which `ZIGZAG_MAX_ROW_PITCH_PX` does not bound; no shipping world is within 4x, and that ratio is now the authored guard.) The old amplitude-vs-period collision clamp retired with it (abutting rows cannot smear). `period_px` is now the TOOTH wavelength alone; `amplitude_px` carries the profile, the pitch and the thickness. Dials: Quokka 100px/24px UNCHANGED (its field already covered every margin cell at every swept viewport), Gumtree 170px/60px — the same ~0.35 profile ratio item 86 authored (85/250), the whole field scaled to a pitch a page margin can hold. Recorded cost: Gumtree reads ~6 broad rows down an ordinary window where the first cut read ~3, and that reading is NOT recoverable — a void-free chevron's teeth span its own pitch by construction, so "rows three times the height of their own teeth" and "no blank lane" are mutually exclusive; broadness now lives in the tooth wavelength, the 2.5x pitch ratio against Quokka, and the low density. The draw call is still the LITERAL `pass.draw(0..3, 0..1)` fullscreen triangle (a handful of added fragment ALU ops; zero CPU work, zero new uniforms). Laws: `render/tests/zigzag_ground.rs` — a per-cell OCCUPANCY grid SWEPT over twelve `(window, measure)` shapes (heights 500..1600, aspect 0.56..2.37, including both verified failures) at the app's OWN `TextPipeline::column_left`/`column_width` owner and in BOTH placement regimes; **item 100 gave that headline law its teeth** — it had SURVIVED the exact regression it names (1.43x its floor against 5.48x healthy) because a 3x3 partition makes cells up to 116x266px, so the cell is now DERIVED from the field's own geometry (`P*|sin a|` by `P*|cos a|`, the smallest axis-aligned rect whose across-travel chord reaches a whole row pitch: Quokka 41x30, Gumtree 33x122) and the ink floor is a twentieth of the field's own structural areal density `2t/pitch` rather than a bare non-zero — 4712 cells graded, tightest occupancy 1.5x the floor, and 1595 cells at literally zero ink once the pitch rule is reverted. Item 100 also PINS the residual that grid deliberately does not claim (`zigzag_sub_pitch_voids_stay_isolated_pockets_never_a_lane`): below the minimal cell, ~30x100px lens voids exist between neighbouring ribbons (67 of 1424 sub-pitch cells on Gumtree, 3 on Quokka) — unavoidable for any sparse row field and closable only by a denser authored dial, so their SHAPE and POPULATION are bounded (no blank cell may touch another; ≤8% blank) instead of failed on, and both bounds go red at the broken pitch rule. Also: a no-blank-LANE law scanned on the ACROSS-TRAVEL axis (a screen-`y` scan cannot see a lane once the angle is nonzero — the trap that hid this); an EVENNESS bound pinning the widest fully-blank horizontal band of any swept margin (174px as first shipped → 60px at real GPU pixels); the abutment THEOREM over 1600 arbitrary dial settings; an authored row-pitch bound (`theme::ZIGZAG_MAX_ROW_PITCH_PX`); a row-rhythm law; a height-scaling law; zero mark ink inside the writing column; byte-determinism at two canvas sizes; a WGSL structural tripwire on the fold AND the abutment rule; and a host mirror kept in lockstep with the GPU, carrying the first cut's pitch rule as a second arm purely so the laws can be proven capable of catching what it did. All pixel claims are DIFFERENTIAL (the world as authored minus the same world with `density: 0.0`, so gradient + dither + quantization cancel exactly and the measurement is the mark alone) — `mark_field` is that oracle's one owner, reused by item 86's contrast law.
- **ITEM 158's DECKLE margin ground** (`theme::Background::Deckle{ground,layer,deckle,weave,period_px,wander_px,density}`, shader id 9) — the handmade-paper MATERIAL field, and the roster's tenth ground. Quasi-random CONTOUR LANES, seeded per lane index and torn by a fixed two-tone sine wander, drawn only in the margins and computed entirely from the fragment position plus the page column. Static: no clock, no texture, no asset. ONE theme-owned dial, `theme::Weave`, picks the profile — `Strata` indexes the lanes on DISTANCE FROM THE PAGE COLUMN (so the contours gather around the writing page and MIRROR across it by construction; Paperbark's) and `Fibres` indexes them on screen `y` as thin strokes plus a diagonal vein family (reusable, DORMANT, the `Bands` / `Dots { edge: true }` shape — item 159 is its intended first assignee, and adopting it is one word in a world literal, not a renderer change). The scalar rides `params.w` through the new `BgDesc::weave` slot, whose INERT default is `0.0` for every ground with no weave (`Background::weave_mode` is the one owner); pitch/wander/density take `params.x/y/z`. `density == 0.0` collapses BOTH profiles to their flat ground EXACTLY — that is deliberate, and it is what gives the family item 86's `mark_field` differential oracle for free. Coverage is a property of the SHADER, not of a dial pair (item 89's abutment lesson): `deckle_rgb` CLAMPS the authored pitch to `DECKLE_MIN_PITCH_PX`, below which the deckled edge — a fraction of a lane — would fall under a pixel and alias. Laws: `render/tests/deckle_ground.rs`, whose swept axis is the MARGIN'S OWN WIDTH (the lanes are indexed on page distance, so how many a margin can show is a property of that margin, not the window), times 1x/2x DPI.
- **ITEM 186's GROUND COORDINATE SPACE — every authored ground quantity now declares whether it is COMPOSITION or SAMPLING.** Before it, `scale_px`, `period_px`, Dots' 24px cell and Deckle's pitch were all PHYSICAL pixels by accident of the coordinate a fragment shader runs in, so a 2x display rendered a ground at half its logical size and showed roughly twice as many elements — invisible to every law, because a capture is only ever internally consistent with itself. Item 176's crisp countable grammar is what made it structural rather than a texture difference. **COMPOSITION** (a cell, a pitch, a mark size, a wander, a reach) is now LOGICAL, so matched logical canvases show the same composition at any density; **SAMPLING** (an antialias feather, the banding-kill dither cell) stays PHYSICAL, so a better display resolves that same composition more finely. The distinction is DATA, not a shader convention: `theme::ground_space`'s `GroundSpace` + `Background::authored_quantities` is a wildcard-free per-variant table naming every number, its class and why, and `shaders/background.wgsl` is the consumer — ONE conversion of the fragment position (`to_logical`, fed from `BgDesc`'s new `scale`, which is `TextPipeline::dpi` alone and NOT `metrics.scale`, since a ground has never scaled with text zoom) and ONE owner converting a physical feather back into that space (`sampling_feather`). The page-column punch and `bayer_threshold01` deliberately keep the device pixel. The judgment calls are the deliverable and are recorded in THEMES.md's own section: a floor whose motivation is sampling (`FINDS_MIN_SCALE_PX`, `DECKLE_MIN_PITCH_PX`) is still a floor on a COMPOSITION quantity and stays logical, or the clamp hands the composition back to the display where it binds; a soft ramp that is a visible fraction of its own mark (Zigzag's ribbon edge — which also feeds the row pitch through item 89's abutment rule — Deckle's fibre ramp, a lane's torn boundary) is drawn character, not a sample-grid resolve; item 176's 0.75px `FINDS_EDGE_AA_PX` is the canonical sampling quantity and did not move; `Bands` and `Lava` were already density-independent through viewport-fraction authoring and are named in the table so that absence is on the record. Laws: `render/tests/ground_space.rs` (roster-wide composition identity by cross-correlation of the 1x field against the box-averaged 2x one, the feather's ramp-width invariance, no-wildcard completeness, and a WGSL structural tripwire). A 1x/2x visual sheet confirmed this by eye at the time; the capture that produced it is retired, and the laws above are what still runs.
- **ITEMS 132/194/268's WARPED-GRID margin ground** (`theme::Background::WarpedGrid{ground,minor,major,tunnel,spacing_px,density}`, shader id 10) — the roster's ELEVENTH ground and its only TRAVELLING one, and Kite's alone. ONE camera at a FIXED point, ONE circular cross-section: `warp_room_axis(vp_x)` (`shaders/background.wgsl`) returns `vp_x * 0.5` and nothing else — no page term, no margin term, and, the point of item 268, no SIDE term, so there is exactly one vanishing point in the room and it sits BEHIND THE PAGE. Each margin is one flank of that single tube. The projection is closed-form, not an inversion: `w = p - axis`, `u = length(w)` is the projected radius and `atan2(w.y, w.x)` the polar angle, so a RING is a level set of `log2(anchor/u)` (a true circle, not an ellipse — there is no bend to make one) and a RAIL a level set of angle. **`Tunnel::PerMargin` does not exist** (`grep Tunnel:: theme/ground.rs` — the enum's four arms are `Fixed`, `PageScaled`, `MarginPlaced`, `Reversed`); the per-margin axis it would have named, `warp_window_axis`, is gone from the tree entirely, along with `WARP_WINDOW_INSET`, `WARP_BEND_GAIN` and `WARP_SOLVE_STEPS` — a grep-law (`render/tests/warp_tunnel.rs::shader_has_fixed_geometry_and_no_steering_path`, mirrored in `warped_grid.rs`) asserts all four absent from the WGSL by name. That per-margin axis is what the user saw as "two tunnels" and every law of the day passed, because they graded the field's scale, density, travel and aliasing — all of which a second camera preserves exactly — and nothing asserted the two flanks were views of the SAME cylinder. Forward travel is one ADDITION to the ring's own coordinate, `let travel = select(g.warp_travel, -g.warp_travel, reversed); let ring = rpo * log2(anchor / u) + travel;`, so every ring's projected radius GROWS and the lattice sweeps outward past the reader; `Tunnel::Reversed` flips the sign and the world recedes instead. **There is no steering pose.** `crate::warpgrid::route_pose` does not exist (`grep -r route_pose src/` is empty) and `background.rs`'s `Globals` struct carries no `pose` field — `render/tests/warp_tunnel.rs` and `warped_grid.rs` both assert `"g.pose"` absent from the WGSL by name. `src/warpgrid.rs` owns only the ONE thing left to steer: continuous forward travel (`LOOP_SECONDS`, `FORWARD_CELLS_PER_LOOP`, `should_travel`, `forward_cells`, `advance_phase`) — a phase in seconds, not a pose. The SCALE is the ROOM's and never the page's: `WARP_SECTION_ROOM_FRAC` (0.432) sizes the anchor ring's radius against the room's own height alone, and the section is a circle — no affine fit — so the projected cross-section measures aspect 1.00 and one fixed radius at every page width the adaptive column reaches, over the whole `page::MIN_MEASURE..` band (`render/tests/warp_tunnel.rs::fixed_framing_is_room_owned_across_page_width_and_offset`). **Since item 268 the page column is VEILED for this ground rather than punched** — `fs_main` declines the hard punch for `g.shader == 10u` alone — to `WARP_PAGE_VEIL` (0.13), with the minor lattice and the whole rail family retired at the page edge so that only the sparse major RINGS share space with prose; that crossing is what makes "one tunnel" legible (a ring leaving the left flank has to arrive in the right one at the same radius) and is held to a real-composite legibility floor, not taste (`render/tests/warp_one_tunnel.rs::the_under_page_crossing_clears_the_body_ink_legibility_floor`). `theme::Tunnel` carries `Fixed` (the only profile a world authors — Kite's) plus three DATA-ONLY mutation arms that mutation-prove the invariants above by breaking them on purpose: `PageScaled` (round 1's page-derived scale and flattened aspect), `MarginPlaced` (round 2's per-margin window placement, `warp_window_hide`, kept alive to prove the room-owned framing is a real constraint and not a vacuous one), and `Reversed` (the inverted travel sign). The scalar rides `params.w` through `BgDesc::tunnel`, inert `0.0` for every ground with no tunnel; spacing and density take `params.x`/`params.y`. `density == 0.0` collapses the field to its flat `ground` tone EXACTLY (`warped_grid.rs::zero_density_is_an_exact_flat_ground_reference`), which is what gives the family item 86's `mark_field` differential oracle. Laws: `render/tests/warped_grid.rs` (roster, the under-page veil, hierarchy, edge fade + the crossing, no-moire, narrow simplification, the exact wrap, the zero-density reference, the no-steering-path grep), `render/tests/warp_one_tunnel.rs` (the field under the page is a function of radius alone, a ring found at every angle where one tunnel predicts it, the ladder held at two `capture-dpi` scale factors, and the under-page legibility floor) over twelve `(window, measure)` shapes x named travel phases, and `render/tests/warp_tunnel.rs` (room-owned framing invariant under page width/offset, the two page-owned mutation arms breaking it on purpose, forward travel growing the ring ladder at the authored rate, `Reversed` receding, and the no-steering-path grep). **The travel phase advances on the HOT per-frame loop, not the ~10 fps ambient tick every other time-varying ground rides** (`TextPipeline::advance_warp`, gated by `warpgrid::should_travel`, which wraps `lava::lava_should_tick`): those grounds drift, this one travels.
- `is_one_bit()` still exists (pins Wagtail's identity for the monochrome law tests) but the renderer no longer reads it. **Grep-law `theme_caps_law`:** fails if `.is_one_bit(` or a quoted world name appears in real code under `src/render/` — structurally bans a future per-theme special case.
- **Lava frost is an ORGANIC glyph-seeded FIELD (item 32), not rectangular pills.** The lava worlds (Mangrove + Firetail) keep both margins alive and frost the drawn margin ink (outline + gutter). Every visible margin glyph SEEDS a small close halo `[x0, x1, yc, r]`; the shader SUMS the halos into one continuous scalar field and thresholds it (`lava::frost_coverage`), so neighbours MERGE in any direction — nearby words/rows become one organic island, a group-gapped row separates, with NO per-row rule and NO zoom breakpoint (topology falls out of the continuous field). The ROW's radius ceiling is derived from the ZOOMED LABEL row height + the shared renderer-owned `lava::FROST_FEATHER_PX` skirt (`render::frost_seed_radius`); `FROST_DIM` and `FROST_BLUR_PX` live beside it. Both lava worlds share that one no-variation recipe; only their `Background::Lava` palette data differs. Owners: `TextPipeline::outline_frost_seeds` + `gutter_frost_seeds` → the shared `render::push_text_seeds` (per-glyph or the word-run degradation arm, `lava::FROST_SEED_PER_GLYPH`); the seed field is a PROTO-CACHE (`frost_seed_key` / `frost_seeds`, rebuilt only on a viewport/zoom/column/margin-text miss — witnessed by `--bench-frost`). All non-lava worlds stay byte-identical (empty seeds → inert shader path).
- **EACH SEED's own radius is PUNCTUATION-AWARE and BOUNDED, not a blanket row value (item 61).** The row's `frost_seed_radius` is a CEILING, not every run's literal radius: `render::frost_run_radius(r_row, run_ink_w, skirt)` takes the tightest of three — `r_row` itself, the run's OWN measured ink half-width (× `lava::FROST_RUN_INK_RADIUS_FRAC`) plus the skirt, and a BOUNDED END-PAD ceiling (`skirt × lava::FROST_END_RADIUS_SKIRTS`, independent of row height). An isotropic seed's `(1-(d/r)^2)^2` falloff is symmetric, so a near-zero-ink run at the FULL row-height radius reads as a bare circle hung off the glyph (an isolated `&`, a one-letter heading) instead of a close hug — the ink-derived bound ties that run's own radius to ITS OWN advance geometry instead. The end-pad ceiling separately caps how far a LONG single-run label's halo can reach past its own final glyph (a hyphenated compound like "Button-free" has no internal whitespace to break it into shorter runs) — a bound that does NOT grow with a taller row (a deep heading-ladder rung, a big zoom), only with the skirt. An ordinary multi-glyph run's ink half-width and the end-pad ceiling both already sit at or above `r_row` in practice, so `min()` is a no-op there — row/nearby-run merging for ordinary text is unchanged. No glyph or label is identity-matched; the bound is purely geometric. Laws: `render/tests/frost.rs`'s `isolated_punctuation_run_radius_is_bounded_below_a_normal_runs`, `long_run_end_pad_is_bounded_independent_of_row_height`, `nearby_ordinary_runs_still_merge_after_the_bounded_radius_round`.
