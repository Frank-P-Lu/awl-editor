## The summoned workspace (`overlay/workspace.rs` + `render/chrome/workspace.rs`) — item 114

- **THE THIRD OVERLAY GEOMETRY FAMILY**, beside the flat pickers (`overlay_geometry`) and the grouped/faceted card (`theme_overlay_geometry`). `overlay_geometry` dispatches to it FIRST, on `overlay_is_workspace()` — a workspace's rail IS its facet strip stood on its end, so the same `overlay_lens` data reaches a different presentation and the faceted branch must not claim it. A workspace's box comes from the CANVAS (`workspace_margin`, a fraction of the smaller window dimension, clamped) rather than from a width cap and an anchor rail: it is not a card looking for a comfortable place to float.
- **WHICH KINDS, AND WHICH SHAPE**: `OverlayKind::workspace_shape` (wildcard-free) returns `Option<WorkspaceShape>` — `Some(shape)` names the arrangement a kind is PRESENTED as, `None` keeps it on its contextual or grouped card. That match is the roster; this doc does not restate its membership. Deliberately NOT `sustained()` — that predicate says a kind has workspace LIFECYCLE (item 173 gave both Settings and History a detail stage and a Back); this one says it is PRESENTED as a relocated workspace, and as which shape.  The renderer never re-tests the kind: `ViewState::overlay_workspace` is the projection, and `actions::tests::workspace_item114::no_second_place_decides_how_settings_is_presented` bans a second test inside `render/chrome/`.
- **ITEM 116a — ONE SHAPE WAS NOT ENOUGH.** `workspace_shell()`'s bare bool put facet LABELS in the primary column and ROWS in the content pane unconditionally — the right composition for Settings, the wrong one for History's "narrow timeline beside a large comparison" (DESIGN.md §5). `WorkspaceShape` names both arrangements (`RailOverRows`, `TimelineOverComparison`), and `WorkspaceShape::rows_are_primary()` is the single fact every consumer reduces to instead of re-deriving which region holds a workspace's own rows — the only match over the enum's variants anywhere in the crate (`render::tests::workspace_shape_item116a`'s grep-law keeps it that way). `workspace_geometry` reads it (via `ViewState::overlay_rows_primary`, a flattened bool mirroring `overlay_workspace` — the render layer still never touches `WorkspaceShape` itself, consistent with `theme_caps_law`'s "render never branches on identity") to decide which of the primary column or the content pane carries the row-window (`text_left`/`text_w`, `visible`/`top_idx`) and which, when rows are primary, becomes a rect this module never draws into (item 116b's future comparison viewport). `rows_are_primary()` is the single fact each consumer reduces to, and it is `true` exactly for `TimelineOverComparison` — so the arm is LIVE, not a structural generalization awaiting an occupant. Which kinds take it is `workspace_shape`'s own match, not a list here.
- **Focus and lifecycle.** `detail_focus` distinguishes the category rail from the detail pane. Settings adds `SettingsFocus::{Categories, Search, Controls}` inside those stages, owned by `Journey`; Tab and Shift-Tab cycle the available recipients, skipping Controls when search has no matches. `settings_workspace_intercept` routes keyboard input before generic picker handling. Esc leaves from either lifecycle stage; child auditions still return to their parent. `settings_focus_hint` describes the keys for the active recipient. History retains the generic workspace focus route.

- **WIDTH ENTERS ONCE**, in `workspace_is_wide(width)`: room for the rail plus a content pane that can still show a row's NAME and its VALUE (`MIN_PANE_CHARS`, a legibility floor — below it `rowlayout` starts yielding the secondary column, and a settings list that shows what a setting is called but not what it is set to is not a settings list). Wide draws both regions; narrow stages them, and the same focus fact becomes which stage you are on. No lifecycle transition can see width (`landing_of` has no width parameter), so Back means the same thing in both by construction.
- **THE RAIL'S GRID RIDES THE ROW PLAN.** `OverlayGeom::rail` carries the COLUMN only (`[x, w]`); `workspace_rail_box(geom, plan)` seats it on `plan.first_top()`, so a rail entry and the settings row beside it share a line by construction and the shaped labels, the active mark and `workspace_rail_at` all read one grid. `OverlayGeom::band_x`/`band_w` is the one owner of the CONTENT band's horizontal extent — the card for a contextual overlay, the pane for a workspace — so the plan, the selected-row quads, the bar plates and `overlay_row_at` all stop at the rail without knowing it exists.
- **THE FOCUS CUE IS VALUE, NOT DECORATION.** The unfocused region's marker is the same rect at `UNFOCUSED_MARK_ALPHA` of its alpha (`workspace::dimmed`). The rail's active mark rides the existing `overlay_lens_underline` pipeline (it IS the active-lens mark) but bypasses the `FacetStyle` skins on purpose: those describe a horizontal chip run and say nothing about a column, so the rail takes the world's own selected-row band instead. A workspace draws ONE card surface — item 50's split composition is a small-card gesture and would cut the rail in half.
- **ITEM 116d — THE COMPARISON IS COMPOSITED, *ON* THE WORKSPACE SURFACE (user decision 2026-08-02).** 116b relocated the document's GEOMETRY and stopped; the card still drew over it. The comparison now sits ON the card — one opaque surface, "A WORKSPACE IS ONE SURFACE" intact — and the document's CONTENT is submitted AFTER `draw_overlay_card`, into the carved region, **without re-drawing its own ground**. The rejected "window through it" arm would have shown the BACKDROP's ground (the punch is at the page column, not at the region) and, on a blur-eligible world, frosted the frame AROUND the workspace — exactly where the region is not. `draw_document_layers` splits into `draw_document_ground` (background/lava/stars/page-frame — the quiet frame, never relocated) and `draw_document_content` (everything composed off the four relocated owners); the ordinary frame concatenates them in their original order, so every non-comparison frame is byte-identical BY CONSTRUCTION. **The blur path captures the GROUND ALONE while a comparison is up**, and `blur_signature` hashes the comparison flag (Settings' workspace and History's would otherwise sign identically at one scroll and keep the wrong frost). `TextPipeline::clip_text_bounds` is the GLYPH twin of item 84's quad clip — the identity off a comparison, an intersection with the region on one — routed by the document text layer, the ornaments, the table grid and the image placeholders; it matters only now, because a glyph that outruns the region would land on the card it is drawn after. 116b's `the_relocated_document_is_geometrically_placed_but_not_yet_composited` was DELETED as its own message asked. Laws: `render/tests/comparison_composite.rs` — the surface still covers the whole region in every world; a differential between two documents that differ in every WORD is perceptibly different inside the region, reaches within two line-heights of both its edges, and is BYTE-IDENTICAL everywhere outside it (the byte-identity is what catches the frosted ghost, measured at max-channel-delta 2); swept over the roster and over canvas × zoom × DPI, with the visibility half graded only where the region can hold four lines.
- **ITEM 116b — THE RELOCATED DOCUMENT VIEWPORT (`render/chrome/comparison.rs`).** awl has exactly ONE prose renderer — the document layer — so a workspace whose content region holds prose has to MOVE it rather than grow a second one (the "infrastructure complexity is a smell" CLAUDE.md forbids). `TextPipeline::comparison_viewport` is that move's ONE owner: `Some([x,y,w,h])` (the content pane) exactly when this frame's workspace carries its own rows in the PRIMARY column (`rows_are_primary`) and the content region is on screen, `None` otherwise — which is every frame any kind can reach today, so the change is structural with **zero pixel change** (proven by a 98-capture world × surface fingerprint matrix, PNG and sidecar, not asserted). The FOUR owners every document consumer already routes through — `column_left`, `column_width`, `doc_top`, `doc_clip_band`, ~45 call sites across `rects.rs`/`layers.rs`/`text.rs`/`geometry.rs`/`scroll.rs` — read it, so caret, selection, washes, wrap width, hit-test and item 84's content clip relocate without learning that anything moved. **The BYPASS is private and enumerated:** the PAGE's own column on the canvas (the ground punch, the star margin band, the frost seed key, the sidecar's `page` block) never relocates and is `page_column_left`/`page_column_width`, crate-render-private, its call sites pinned by name — a second "where is the column" is exactly what becomes a parallel geometry. **MARGIN ORIENTATION YIELDS** (`margin_orientation_yields`): the outline, the gutter, the corner readouts (`wordcount_readout_text`/`notice_readout_text`, one owner each), the page frame, the draggable page edges and the lava frost pills all compose off those four owners and have nothing true to say about a read-only comparison; the outline and gutter reach that through item 34's `overlay_active` gate, which subsumes this one and is watched failing rather than trusted. **THE DIFF PANEL IS GONE, not disabled** — `diff_panel`, `diff_panel_rect`, `prepare_diff_panel`, `DIFF_PANEL_TOP`/`BOTTOM` and the three `diffpanel_*` pipelines are removed; its last consumer really was History (`vstate.diff_panel` was lit only by `opts.preview_text`, set only by `history_preview_for`; `scripts/review.sh`'s diff scene sets `opts.diff`, a sidecar block, through `prosediff::env_capture_render` and never `preview_text`). **WHAT IT DOES NOT DO, pinned as a law rather than absorbed:** the relocation moved the document's GEOMETRY, not its place in painter's order — `render` still submits `draw_document_layers` before `draw_overlay_card` and a workspace's fill is its whole card box, so the region is drawn over (`the_relocated_document_is_geometrically_placed_but_not_yet_composited` names what the composition round owes and fails when it lands). Laws: `render/tests/comparison_viewport.rs` (six), the re-aimed `selection_clip_law.rs`, `capture/tests/panels.rs::history_preview_renders_the_transcript_as_the_document_in_every_world`.
- Laws: `render/tests/workspace.rs` (rail roster, drawn-equals-clickable over canvas × zoom × DPI × stage, wide/narrow staging, viewport-with-a-frame, the focus cue in real differential pixels, and a contextual card's untouched geometry), `actions/tests/workspace.rs` (the keys against `landing_of`, search-moves-into-results, one category state, the Cmd-P deep link, Theme/Caret audition parity), `app/tests/workspace.rs` (TIER 2 — every `SettingId × SettingKind` changed and persisted by real chords; see `docs/harness-reach.md` for why it cannot be a capture).


## Settings in the palette + overlay titles (`overlay/` + `settings.rs`)

- The Cmd-P palette's rows are catalog commands **∪** the surfaced Settings roster (a row like "Reduce motion" — one with no covering command — is fuzzy-findable straight from the palette; a COVERED row like "Keymap" or "Caret style" is excluded there, reachable only through its covering command, `settings::COVERED_BY`). Still one `OverlayKind::Command`; the union is data (`attach_settings_rows`, typed `RowMeta`). Every command has one task category from `commands::task_category`; every attached setting joins Settings. The visible strip is `All · Files · Navigate · Format · View · Tools · Settings · Recent`; typing searches the whole union from any category, while clearing the query returns to the category left in place. Settings names read plainly because their named browse home replaces the unexplained `§` marker. Dispatch parity remains one owner (`dispatch_settings_row`; `close_on_toggle` is the only difference: the palette closes, Settings stays).
- **Every `OverlayKind` names itself** (`OverlayKind::title`, no-wildcard) — drawn as a muted prefix on the picker's input line (Rename/KeepName/Context opt out via `draws_title_prefix`, their own prompt orients). `InsertLink` draws its title too, but as a real FIELD LABEL rather than a lowercase picker verb (`"Link destination"`, keeping the user's own casing) — docs/markdown.md's Insert-link section has the field's own shape. Sidecar `overlay.title`. Commands and Insert-link are contextual choices rather than room takeovers: `OverlayKind::retains_readable_room` projects that typed fact into the renderer, which preserves document value outside the card while keeping the world's authored surface, anchor, material and row composition. Placard worlds keep that composition but fold the remote giant wordmark into the existing modest inline title, adjacent to the query/action it names. Pane and true 1-bit Flat worlds need no extra backing; Bars, Ruled and Diagonal use the shared footprint frost because their gaps expose document ink. This is distinct from `keeps_backdrop_crisp`: the writing remains readable context, not a live row preview.


## Settings RANGE rows — the rail (item 94, `range.rs` + `render/rowlayout`)

- **ONE spec owner: `crate::range::RangeSpec`** (`min`, `max`, `step`, `default`, display `Unit`, `RailMap::Linear|Log`), resolved from a row's identity by the single map `settings::range_spec(SettingId)`. It owns EVERY derivation: `quantize` (the zero-anchored step grid), `step_of`/`value_of_step`, `frac_of`/`value_at_frac` (the rail mapping, both directions), `stepped` (keyboard), `format` (readout + sidecar), `parse` (exact entry), `persist_value` (config RHS). `render::clamp_zoom` is a one-line delegate to `range::ZOOM`, and the old `ZOOM_MIN`/`ZOOM_MAX`/`ZOOM_STEP` consts were DELETED rather than re-pointed — an alias is a drift risk. Zoom: 50 %–300 %, 10-point steps, LINEAR percentage rail. The `Log` map is general (25/50/100/200/400 land on equal intervals — item 90's `scroll_sensitivity`, not built here).
- **The row carries a discrete cell**, `OverlayRow::range: Option<RangeCell{id, step}>` — an integer step, so a row stays `Eq` and the drawn thumb can never sit where the keyboard cannot. Set at build AND at `refresh_settings_overlay`, beside `set_secondaries`, from the SAME gathered `SettingsValues`. `item_range_fracs()` derives the 0..1 column (EMPTY off Settings) → `ViewState::overlay_ranges` → the pipeline.
- **Geometry has ONE owner, `rowlayout::rail_geom`** (track / fill / thumb / hit band / `x0`,`x1`), sized in row-heights so it scales with zoom, seated left of the right-aligned value TEXT (measured from the same shaped buffer the value draws from) and YIELDING entirely when the row lacks room. `chrome::TextPipeline::overlay_rails` resolves the card's rails once; the DRAW path and the POINTER hit-test (`overlay_range_at`) both read it, so the control is clickable exactly where it is drawn. The hit band is padded past both ends and spans the whole row (a generous target around a small thumb).
- **Ink:** track `faint()`, fill + thumb `muted()`, flipped through the shared `theme::selected_row_secondary_ink` when the selected row's band would wash it out — the SAME owner the secondary TEXT uses. It remains secondary to the world's principal interactive ink. Two parked-by-default pipelines (`overlay_range_track` / `overlay_range_thumb`).
- **Input:** Left/Right claim the keys ONLY when the highlighted row carries a rail (checked before the facet-lens cycle, which is otherwise untouched); the step applies IN THE CORE (`Effect::SettingRangeStep` is replay-`Applied`) and the App owns the tail (reflow + the DISCRETE per-step persist). The POINTER: a rail press sets the nearest step and arms `RangeDrag` (press-time track scale snapshotted, the page-drag anchor lesson); every move applies live through `App::range_apply_live`; the RELEASE persists ONCE (`range_persist`). A click on the row's LABEL selects without changing. Enter still opens the exact numeric edit. No Shift/Option variants, no ±buttons, no wheel-to-change.
- **WHEN THE ZOOM PERSISTS HAS ONE OWNER, and one gate.** The write itself is `App::settle_zoom_persist` (persist, disarm the stamp, drop the floating readout, redraw); every door calls it — `about_to_wait`'s ~500 ms quiet window, `range_persist` (the rail's release / a discrete keyboard step), and `setting_value_commit`'s typed entry, which settles at once (a typed commit is its own discrete end) rather than leaving the debounce armed to write the same value again. The quiet window is an INFERENCE of "the gesture ended" for the doors that have no end event (⌘±, ⌘0, ⌘-wheel), so `App::zoom_persist_held` (`range_drag.is_some()`) turns it off while a gesture that DOES have an end is in flight: a live apply arms the in-flight stamp exactly as before (the hold-⌘ peek suppression still reads it), but the WRITE waits for the release. Without that gate, pausing mid-drag to look at the value IS half a second of quiet, and the debounce persisted a value the user never released on. Clock-driven law: `app::tests::files::a_paused_mid_drag_persists_nothing_until_the_release` (VirtualClock + `RecordingScheduler`, the which-key frame-loop pattern).
- **The foot hint is PER-ROW where the row's keys differ from its kind's.** A rail row's footer reads `←/→ adjust`, which is the ONLY `←/→` cell a Settings row ever carries (an ordinary row hands that axis to the region seam and advertises no meaning for it) — `OverlayKind::range_row_hint` relabels that one cell of `hint_actions()` (so the rest of the line can't drift), selected in `OverlayState::foot_hint` on the SAME `selected_range()` predicate the Left/Right claim itself uses, so advertised keys and live keys are one decision. This is an accessibility requirement, not polish: the footer is awl's only statement of what a key does and there is no accessibility tree behind it (ACCESSIBILITY.md). Outcome law: `actions::tests::overlay_drive::the_foot_hint_names_what_left_right_actually_do_on_every_settings_row` (drives the real `ForwardChar` on EVERY Settings row and asserts the line named what happened); the footer's no-clip sweep measures both variants.
- Laws: `range::tests` (grid/round-trip/log-interval/drag-equivalence/parse), `settings::tests` (the no-wildcard kind-contract sweep + end-to-end range wiring), `render::tests::range_rail` (pure geometry, drawn==clickable, thumb travel, light/dark real-pixel contrast), `app::tests::files` (one-persist-per-drag, discrete keyboard persist), `actions::tests::overlay_drive` (keyboard steps + the lens-cycle gate + parity), `capture::tests::pickers_faceted` (sidecar `overlay.ranges`).
